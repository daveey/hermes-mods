# Evidence-based work state observations (execution observations v1)

Patches: **2679–2697, 2908–2909**. The latter pair documents the remote Board-replica follow-up requested for **PR #1663**.

## Behavior

- One versioned, pure projection (`project`, `select`, `summarize`) maps source-qualified evidence (kanban card rows, turn leases, processes, subagents, completion receipts) to a work state: `running | queued | waiting | needs_user | done | failed | cancelled | unknown`. The Python implementation and the TypeScript one load the same fixture file, so verdicts are defined once.
- `observed_at` and `valid_until` belong to the source that produced the evidence. A fetch, copy, memo hit or file mtime never renews them. Expiry is time-only: when the render clock passes `valid_until` (bounded by 180 s for the sidebar class, 600 s for imported-owner) the state becomes `unknown` with the previous state kept as `last_known_state`; no refetch or new timer is needed (the desktop re-evaluates on its existing 15 s observation tick).
- Missing or invalid identity, owner, evidence references, timing or attempt (`run_id`/`generation`) yields `unknown`, never success, failure or "stalled". A legacy producer that sends card counts but no `execution_observations` array shows an explicit `unknown` for its live (unparked) cards; parked waits keep their legacy wait. A current producer always sends the array, even an empty one, so desktop never mistakes it for a legacy one.
- Structured human requests stay outstanding through expiry, conflict and adapter failure; verified `delivered` receipts remain as history (`last_known_state: done`) but never turn a current `unknown` into success.
- `done` is only reported for a card whose completion is verified, whose admitted receipt has every item `delivered`, and whose receipt, completion event and closing run are one exact qualified execution. Archive, cancel and an unverified or stale "done" are never success (a replayed or stale done is `unknown`).
- Optional `execution_observations` arrays are added (additive, advisory; legacy fields unchanged) to the Kanban session activity and session-tasks responses, to card detail (`kanban_queue_position.py`), to `process.list`, `subagent.list`/`subagent.roster` rows and the session lists. Existing outcomes, receipts, admission and human-request handling remain authoritative.
- Desktop: the session dot and sidebar row (`session-dot-state`, `execution-observation-row`) summarize running+queued, waiting, needs-you, unknown and outstanding-ask counts per row. No evidence, or a failed source, gives no summary (not proof of zero work).

- **2908–2909 (PR #1663):** with `links_reader=replica`, a remote running card can now carry source-qualified running evidence from its current executor attempt. Its identity uses the run's portable UID, `observed_at` is the newest current-run `heartbeat`/`claimed`/`spawned` event's `created_at`, `valid_until` is that time plus **180 seconds**, and revision/evidence reference is **`event:<uid>`**. Pull/fetch time never renews it. Session-task projection and the sidebar-count evidence sink use the same raw record. Missing evidence, old-run-only events, ended/released runs, parked cards, future clocks and a guessed owner profile stay explicit `unknown`; an origin-ledger fallback label `default` is not owner evidence. A ledger row explicitly naming profile `default` is different and may qualify.

## How it works

- **2679** adds the pure projection in `hermes_cli/execution_observations.py` and the TS mirror `apps/desktop/src/lib/execution-observations.ts`, the shared fixture `schemas/fixtures/execution-observations-v1.json`, golden tests in both languages and `docs/execution-observations-v1.md`. It defines strict attempt/identifier validation, own-property TTL lookup, human-request validation (private `resolved_check*` probes stripped), progress rules, `last_known_state` rules and order-independent `select`.
- **2680** makes uncertain selection retain evidence: `retained_human_requests` and `historical_delivery_receipts` (structurally deduplicated, canonically ordered, exact matched identity only) are carried when `select` ends `unknown`, and summarization counts retained plus singular requests once per observation.
- **2681** isolates a requested execution's history: an expected-identity mismatch returns only the requested identity (no foreign asks/receipts) with reason `execution_identity_mismatch` or `invalid_requested_identity`; `select` with no match returns `no_observation`. Freshness validation is split from identity checking.
- **2682** wires cards into the product: new `hermes_cli/kanban_execution_observations.py` (card adapter `card`, `add_cards`, `count_snapshot`) and `kanban_execution_source.py` (source snapshot read), `execution_observations` on activity/session-tasks/counts, process and turn-lease adapters (`turn_process_execution_observations.py`), and the desktop store pieces `execution-observation-row.ts`, `session-dot-state.ts`, session row/tab accent, an observation clock hook and SDK export. Counts alone stay `unknown`: a snapshot is not an observation of its workers.
- **2683** isolates optional adapter failures per card: an adapter exception (`ADAPTER_ERRORS`) is logged and that card gets an explicit `unknown` (`failed_card`) while legacy output is unchanged and other cards are unaffected.
- **2684** keeps asks and remote ownership on adapter failure: human requests from the existing count rows survive the board assemble fallback without another query, and a remote failed card uses only the remote gateway and `owner_profile` (legacy `profile` only when `owner_profile` is absent), never local defaults.
- **2685** projects qualified process and subagent evidence across RPC and sidebar: wait-row code is split into `kanban_session_wait_rows.py`; process/subagent observations flow through `process.list`/`subagent.roster` (OpenRPC contract updated) and a desktop live-work roster that merges row, roster and event-fed evidence per owner route.
- **2686** unifies process identities across producers: one registry process is no longer counted twice because rows stamped the launch profile while RPCs stamped the served profile; same-probe copies are re-projected at the consumer clock before exact-identity selection so request-derived age does not create false conflicts.
- **2687** adds completion receipts as done evidence: `kanban_completion_inputs.py` (batched completion reads), `kanban_execution_receipt.py` (`done_raw`, counts and session-task attach), receipt projection and recent-done changes. Done observations live in an observation-only `done:` bucket and are never counted as open work. No new store, writer or schema.
- **2688** unifies persisted and registry child activity: `subagent_session_activity.py` annotates session lists with the canonical `subagent.activity` observation (work id = child session id) from a read-only per-profile state read (one batched SELECT per three seconds, six-hour discovery window, 180 s staleness); read failure is `unknown`, absence never proves zero children.
- **2689** adds tests that drive persisted child observations through the HTTP sidebar entrypoints (test-only).
- **2690** exposes the canonical child activity on native `subagent.list` rows (`gateway/session_ancillary.py`); on adapter failure the field is an empty list and roster discovery is unaffected.
- **2691** review fixes for receipts: completion verdict inputs are no longer payload-size-capped, any exception from one card's evidence is that card's unverified verdict (not a failed batch), the latest `completed` event is chosen by id, and a stale done is `unknown`.
- **2692** is the health-gate follow-up: fixture alias and a logged per-card verdict fallback (`kanban_completion_inputs.py`).
- **2693** makes local card identity use the board-root owner profile (`board_owner_profile`: board under the root is `default`, under `<root>/profiles/P` is `P`, outside the root unknown), not the reader's active profile, in list, sidebar-count (including done receipts) and card-detail paths.
- **2694** is test-only: aligns four poll-read regressions with the additive (unknown) observation on replayed rows, the extra `boards` entry in a spies dict, and the bounded per-board counts source age.
- **2695** keeps a failed open-card source's board-root owner identity and lets an independent verified receipt project `done` despite that failure (receipts are read whenever owner authority holds; a mirror still attests nothing).
- **2696** makes legacy producers explicit unknown in the desktop row, keeps asks when the roster source fails (each cached record becomes an explicit unknown under its own identity), and makes TS treat a null expected identity as "no fence", matching Python.
- **2697** makes a board-scoped failed card keep its own profile (none on an unrooted board), stamps scope before assemble in card detail, and makes `count_snapshot` keep an empty array for open work without a card record. It also fixes two tests: one gateway-capacity integration test pins the gateway name instead of reading host state, one tool test emits only the asserted field.

- **2908:** add `hermes_cli/kanban_replica_execution.py` and attach `_replica_run` only when `kanban_chat_links.replica_cards` proves the owner gateway/profile from the unreleased origin ledger. The run must match the card's `current_run_id`, belong to the card, be running and unended. Choose liveness by descending event `created_at`, then portable event UID, not arrival ID; ordinary comments are activity, never liveness/progress. `raw` builds `source: kanban.replica_run`; stale replicas retain run identity but project `unknown/source_unavailable` with `last_known_state: running`. `kanban_execution_observations.card` consumes this record, `add_cards` strips the private intermediate field, and `kanban_session_activity` collects the same raw evidence for counts. Older schemas lacking run evidence retain the existing explicit unknown.
- **2909:** fix the initial implementation's quiet-board cache trap: heartbeat writes are bookkeeping for `kanban_activity_revision` and do not move the shadow content key. Remove run terms from memoized `_read_replica_links`; call **`kanban_replica_execution.read_runs` on every `_read_replica`**, outside the link-row memo. One constant, bound-parameter query starts at this gateway/profile's unreleased chat links, joins tasks by primary key, and looks up the current running/unended run UID and newest qualifying event. An assertion ties placeholder count to `LIVENESS_KINDS`; missing schema columns return an empty map. `_last_good` retains rows, pull stamp and run map together for stale fallback. `SHADOW_TABLES`, triggers and memo invalidation remain unchanged. Sidebar counts observe new beats on their existing recompute bounds (3-second TTL / 30-second revalidation), not via heartbeat-triggered whole-board invalidation; lag only ages source-dated evidence.

## Gotchas

- For remote replica running evidence, **2908 alone is insufficient on a quiet board**: its run terms were trapped in the link-row memo. Keep 2909's bounded current-run read outside that memo; do not make heartbeat traffic invalidate every board as a substitute.
- Remote liveness is not progress or completion authority. A pull stamp only helps identify an unavailable/stale replica; it never supplies `observed_at` or extends the executor's 180-second lifetime. Parked replica cards intentionally have no invented executor clock. A fresh local read cannot repair a future source clock.

- Absence is not evidence: no observation, an unreadable per-profile store, a child outside the six-hour window or a persist-disabled child never means zero work or completion.
- Expiry only ever yields `unknown`; it never yields failed, stalled or done. Missing progress does not mean stalled.
- `execution_observations` is optional. Older producers omit it and older consumers ignore it; mixed versions show explicit unknown rather than certain work.
- The deterministic ordering of retained requests/receipts is structural, not an ordering of authority or chronology.
- Capacity diagnostics (`kanban.dispatch`/`kanban.capacity`) are context, not a work item in the row summary.
- A board outside the Hermes root has no guessed owner profile, so its card identity stays unqualified and projects `unknown`.
- Observe managed-worker child rows at the owner gateway, not the worker host.

## Plugin

Core change; no plugin required. The `session-tasks` and `session-panel` plugins in hermes-mods are public consumers of the activity/session-tasks responses and may read the optional `execution_observations` field.
