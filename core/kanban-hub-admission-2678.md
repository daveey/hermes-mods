# Evidence-checked hub admission judge

Patches: **2604–2620, 2646–2648**.

## Behavior

- A card bound for the hub no longer holds a hub slot just because its text mentions a hub-state marker. Every hub-bound outcome now needs an evidenced admit from a pinned judge: a hub keeping a card local, an explicit `hub` pin from any gateway, `runs_on=[machine:hub]` (string, padded and comma shapes included), a stay-here pin (`placement=local/here`) on the hub, hub-only lease labels (including `runs_on=[]`) created on the hub, a `hermes kanban move` to the hub, a capability owner card routed to the hub, and a routed (courier) create landing on the hub. Structural limits (`needs`, host workspace, non-default board, uncarried options, assignee) are unchanged and never call the judge. A non-hub gateway makes zero judge calls unless the caller names the hub.
- Judge contract: it answers `{admit, need, evidence, why}`. `need` must be one of `hub_chrome`, `board_admin_key`, `instance_role_ssm`, `user_terminal`, `hub_worktree`, `gateway_key_cli`, `hub_live_process`. An admit is accepted only when `need` is set and `evidence` is a non-empty quote found verbatim in the title, body or `hub_reason`. Anything else is an "invalid admission verdict" deny.
- Fail closed: if the managed subscription pool, the installed rubric skill (`hub-admission-test`), the call, or the 30 s total deadline (route and credential acquisition included) is unavailable, the answer is deny. A response is accepted only when the route reports provider `anthropic`, model `claude-sonnet-5-5` and billing group `subscription`; any other route is denied. A late answer after the deadline is discarded and never cached.
- A denied automatic card is enrolled in the worker pool with `requires: [hub:write]` (Board label `capability:hub-write`). When `kanban.placement.worker_queue` names a live label for this gateway, the denied card gets `runs_on: [<pool label>, ...coordination labels]` instead; it is never pinned to `machine:worker-N`. Courier and origin-bound denies stay worker-first (never queued). A denied explicit hub pin is refused; with no worker pool configured the create is refused ("hub admission denied; no worker pool configured").
- `hermes kanban create` runs the check before any connection: a refusal exits 2, prints `hub_admission_denied` (`--json`: `code: hub_admission_denied`) and creates no card. New flags: `--hub-reason TEXT` (quoted evidence of what only the hub can do) and `--force-hub` (operator override). The `kanban_create` tool gains `hub_reason` and `force_hub`. `force_hub` is refused inside a dispatcher worker (`HERMES_KANBAN_TASK` / `HERMES_KANBAN_WORKER_TASK` set) and otherwise recorded as a forced verdict with the session id.
- Every verdict is persisted as a `hub_admission` event (and in the creation audit); a denied move returns `hub_admission_denied` and a failed judge `hub_admission_unavailable`. `kanban_show` returns the latest verdict (`hub_admission` field, a `hub:` line in the CLI, and an addition to the queue note).
- The routed placement note (the origin's own host needs, e.g. a browser profile or keychain) is stripped before judging: it is never hub evidence.
- Capability owners: the judgement happens at relay time on the hub, never inside the 30 s `wait-check` probe. An unavailable verdict fails retryably (`hub_admission_unavailable`, up to generation 5, each retry a fresh relay). A stored verdict that fails validation, or relayed owner text that differs from the hub's own rebuild of it, is a final deny to the pool. An owner card is created with exactly the judged text. An owner sent to the hub is judged by the hub's own create. A non-hub home makes no model call.
- A re-applied courier request reuses the placement stored by the first apply (no second judge call, no `origin_creation_conflict`).
- Comment-relay rule (2646–2648): a card whose title writes a comment/note/evidence/result onto another card, with relay wording (`verbatim`, `hub-owned`, `foreign_card`, `replica`, `only the hub`, …), is denied by a deterministic rule with no model call; the refusal text names the route: `kanban_supervisor_request(ops=[{op: 'operator', action: 'comment', ...}])`, or `hub-comment <card> --text|--file [--board B]` on a `capability:hub-write` worker. The rule applies to create (an explicit `machine:hub` pin is refused with that route), move and courier paths. It leaves the card to the judge when the text or `hub_reason` names any allowlist context (Chrome, Cloudflare access, admin key, instance role, SSM, user terminal, hub worktree, `hermes-hub` / the hub gateway's own key, in-process or live hub state, Desktop session, signed-in browser, board admin credential, or a literal need id), or when no explicit target card is named (`on|onto|to <card id>`, a `## <card id>` heading, `hub-comment <card id>`, `task_id=<card id>`).

## How it works

- 2604 adds `hermes_cli/kanban_hub_admission.py`: `Verdict`, rubric loading (`devops/hub-admission-test/SKILL.md` or `hub-admission-test/SKILL.md` under the profile or configured external skill roots only; never a repository's project skill), `validated`, `admit`, and a verdict cache in `kanban/hub-admission.sqlite` (1024 newest rows). 2605 revalidates a cached payload on every read and adds the trusted-root rubric lookup; the cache key covers title, body, `hub_reason` and the rubric hash. 2611 adds the total-deadline wrapper (`_bounded`, a daemon thread holding no lock or DB handle). 2613 makes the rubric read BOM-tolerant (`utf-8-sig`).
- 2606 adds `hermes_cli/kanban_hub_admission_placement.py` and wires `apply` into `kanban_placement.py` / `kanban_tools_placement.py`; 2607 carries the verdict and effective `requires` into creation records and emits the `hub_admission` event; 2608 narrows judging to hub-bound placements.
- 2609 gates CLI create (`cli_preflight`, `cli_plan`, `cli_create_fields`), move (`gate_move` called from `kanban_move.py`), capability owners (`kanban_capability_routing.py`, `gate_owner`) and show (`kanban_show.py`), and adds the parser flags and tool schema fields. 2613 and 2617 only move code to keep `kanban.py` / `kanban_tools.py` within their line caps (`kanban_cli_body.py`, `kanban_tools_attach_url.py`, facade helpers).
- 2612 updates the `kanban_placement.py` docs: markers only nominate a card for the judge.
- 2614 adds `courier_plan` (judged before the create transaction, never under the SQLite write lock), stay-here and structural keeps, normalized `runs_on` shapes, relay-time owner judging, and records in-transaction denies as events. 2615 moves the courier judging into a placement sibling (`kanban_tools_placement.py`) to respect the create handler's cap. 2616 makes owner cards use the judged text (shared builder), stores it on the route, adds `stored_owner_verdict` / `_prior_landing`. 2619 has the hub rebuild relayed owner text (`mismatched_owner_verdict`) and judges `RELAY_RETRY` parks on the hub only. 2620 adds `pool_route` (worker-queue routing for denies).
- 2646 adds `hermes_cli/kanban_comment_relay.py` and makes `kanban_comment_relay.verdict` the first rule in `admit()` (`model="rule:comment-relay"`). 2647 adds the gateway-key and live-process contexts to the allowlist and requires an explicit target card. 2648 adds the Desktop-session and remaining literal allowlist ids.
- 2610, 2618 are test-only (see Tests).

## Gotchas

- The rubric skill `hub-admission-test` is not part of these patches. If it is not installed under the profile or a configured external skills root, every judged placement is denied (`admission unavailable`), so hub-bound cards go to the worker pool and explicit hub pins are refused until it exists.
- The judge needs the managed subscription route; a profile without it denies everything judged. The model id and provider are fixed in `kanban_hub_admission.py`.
- Verdict cache keys include the rubric hash, so editing the rubric invalidates cached verdicts.
- The comment-relay rule is regex based and deliberately narrow (title must open with a post/relay/leave/add/write/deliver/forward/copy verb); a relay-shaped card that fails any condition goes to the model judge instead.
- In an open SQLite transaction no model call is made: the verdict is a deny recorded as `hub_admission_unavailable` (move) or an unavailable owner verdict, never a wait on the judge.
- `force_hub` is an unaudited-by-judge override: it is only recorded (with session id) and is refused inside dispatcher workers.
