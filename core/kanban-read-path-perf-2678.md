# Kanban read-path performance: memoised reads, read-only probes, incremental refresh

Patches: **2578, 2581–2584, 2589, 2592, 2593, 2595, 2656, 2657**.

## Behavior

Eleven independent read-path optimizations found by profiling an always-on hub (many serve threads, a replica of ~12.7k task rows, a main board committing ~40 times a minute). None changes a response shape or a cadence; each answers from memory only while a cheap identity check proves nothing it depends on moved, and otherwise falls back to the full read. Perf-only: no new tool, CLI flag or setting.

- **2578, cached board reads.** A cached read no longer rescans `/proc/self/fd` (the stranded-sidecar scan) or re-resolves the board path on every call under the board lifecycle lock. Fewer "busy; reused last counts" warnings under thread contention. A newly retargeted symlink is seen within 30 s; relative board paths are never cached.
- **2581, remote-links memo miss.** A miss re-reads only replica rows whose `seq` moved and re-projects only those rows, instead of re-reading, re-decoding and re-projecting the whole replica under the links lock. A replica without `seq`/`version`, a row without `seq`, a replaced file, an in-place rewrite or any total that does not add up falls back to the full read. Both paths emit rows in `(gw, key)` order and give identical results.
- **2582, origin projection.** Each owner gateway's inventory row is decoded once per origin projection rather than once per obligation. A decode error is still raised for every obligation that needs it.
- **2583, remote-notice observations.** Pollers no longer queue behind the observation-ledger write inside `observe`'s lock. Concurrent polls still agree on every `first_seen`; an older snapshot never overwrites a newer memo.
- **2584, notice claim and orphan recovery.** Every chat's poller no longer opens a write transaction on the board every few seconds with nothing to do. Only a row with an unseen event of a notify kind, or an in-flight claim due a rewind, takes the write lock. Claim exclusivity is unchanged: a live foreign claim is left alone, a dead holder's claim is still recovered and delivered.
- **2589, notice poll gate.** A chat's notice poll is gated on what it could actually claim (newest deliverable-kind event id plus the chat's own subscription rows), not on every board commit, so heartbeat, claim and run-stamp commits do not trigger a full claim poll. A remote replica commit with no new terminal state opens no observation ledger. A found session lineage chain is reused for 30 s.
- **2592, annotation and links refresh.** Heartbeat events no longer move the board's activity-revision key (the card-details strip still shows the latest heartbeat). A published remote-links entry stays fresh when only boards it never read committed. The attention pass reads recent-done rows once per (scope, board) while the board's memo key holds.
- **2593, follow-up to 2592 (review fixes).** If the recent-done memo key cannot be computed (unopenable board) the board is read directly and never cached. A links slug shared by two boards counts as read on both.
- **2595, `GET /boards`.** Board counts are kept per board db path and reused while the board's observed version is unchanged; the projects db is opened only when a listed board has a `project_id`. The board-row observer limit rises from 4 to 16 so five or more live boards do not evict each other every poll.
- **2656, board refresh after a commit.** The retained board rows are updated rather than rebuilt: unchanged task rows reuse their parsed objects, events are re-read only for tasks whose row, runs or event marks moved, and done cards past the column cap are ranked on a narrow read and never parsed whole. Results match a cold read.
- **2657, refactor.** Moves `list_tasks`/`list_task_rows` from `kanban_db` into `kanban_db_list` (keeping `kanban_db` under its line cap) and makes `board_read` import `kanban_wake_check` lazily, once. No runtime behavior change intended.

## How it works

- **2578** (`kanban_generation`): `_resolved` memoises `realpath` of absolute board paths for 30 s (used by `_path`, `remember`, `evict_readers`). `_stranded` reuses a clean sidecar scan for up to 5 s while the board's `-shm` and `-wal` identities are unchanged; a positive scan is never reused and stale or poisoned boards always rescan. Both caches are capped at 256 entries.
- **2581**: new `kanban_replica_rows` keeps rows keyed by `(gw, key)` and, on a miss, fetches only rows with `seq` above the last seen in one statement; probe totals (count, seq, version, data length) prove deletes and catch rewrites. New `kanban_replica_projection` keeps each row's clock-free projection and rebuilds only aggregates when hub staleness or an owner scope's freshness flips. `kanban_session_activity` and `kanban_session_activity_release` call into them.
- **2582** (`kanban_origin_ledger.project`): per-projection dict of decoded inventories (or the decode error) per owner gateway.
- **2583** (`kanban_remote_observations`): observation rows are insert-only, so states already read or written for a ledger file (by inode) are answered from memory and only unseen states touch SQLite, after commit. `observe` takes its snapshot under `_lock`, writes without it, and publishes the memo only if no newer snapshot started. `kanban_remote_notices` makes the notices-table column migration tolerate a concurrent opener adding a column first.
- **2584** (`kanban_db_notify`): a read-only probe decides first; the write transaction re-checks, so the probe can only skip work, never claim.
- **2589**: `notification_idle.board_signature` is read once per commit for every chat in the process; a table-less file still keys on `data_version` and an unreadable board is never "unchanged". `kanban_remote_observations._persist` remembers `first_seen` per ledger file. `session_notifications._session_lineage` caches found chains; a chat not yet in the store is looked up again. The quiet-board memo, post-poll `board_quiet` proof and in-flight liveness retries are unchanged.
- **2592**: `kanban_activity_revision`'s `task_events` insert trigger skips `kind='heartbeat'`; an older writer's unconditional trigger leaves readers on a valid superset key, and this version's init repairs it. New `kanban_links_narrow` records which local boards a published links entry read; a fingerprint differing only in boards it never read is still fresh (hub replica, ledger, read boards, new boards, undeclared projectors and unreadable rows keep the exact fingerprint; TTL unchanged). New `kanban_session_activity_recent_done` memoises the recent-done read keyed on `board_memo_key`; busy/unknown keys never match, and a later cut-off only filters rows. `scripts/benchmark_kanban_annotation_poll.py` is the synthetic benchmark.
- **2593**: `memoized()` falls back to an uncached read on key failure; `kanban_links_narrow.remember` counts a shared slug on every board it names.
- **2595** (`plugins/kanban/dashboard/board_counts.py`, `board_rows.py`, `plugin_api.py`): counts are keyed on `board_rows.version(path)` (observer generation, dev, ino, schema_version, data_version), read before the count query so a commit during the query is re-read next poll. An unobservable board (`version()` is `None`) is read uncached; a failed query stores nothing; a hit returns a copy; no timer or TTL. `list_boards` calls `_projects_by_id()` only when a listed board has a truthy `project_id`. `MAX_OBSERVERS` goes 4 → 16.
- **2656**: `board_rows.materialized` takes an `update(prev)` used instead of `build` when older rows exist for the key; the board passes the prior rows to `board_read.materialize`. It still reads every task row (a committed write is never missed), reuses parsed `Task`/`asdict` for rows whose values and column names are unchanged, and reads event marks before the events they vouch for. `kanban_db.list_task_rows`/`list_tasks` gain `extra_where` and `parse`.
- **2657**: pure move of the two list functions to `kanban_db_list.py`; `board_read` imports `kanban_wake_check` lazily at one call site.

## Gotchas

- Every cache here trades a bounded staleness for fewer reads: 30 s for resolved board paths and session lineage chains, 5 s for a clean sidecar scan. A symlink retarget is picked up only after the TTL.
- 2592's trigger change applies at init: until a board is opened by this version, an older writer's trigger still bumps the key on heartbeats (correct, just not faster).
- Heartbeat events no longer bump the activity revision, so anything that wants to react to a heartbeat must read the event stream, not that key.
- 2595 has no TTL: a board whose observed version cannot be read (`None`) is re-counted on every poll by design.
