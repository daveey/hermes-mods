# Writing CI, and known CI failure classes

Read when adding a script, test or workflow to a repo's CI, or when a CI failure matches a class below. Waiting on
CI itself is SKILL.md.

## Adding scripts, tests or workflows

- **Where a new tool goes.** Before choosing a directory for a new tool, read the CI workflows' `on.push.paths` and any plan step's path rules. A script under a shared or product directory (e.g. `shared/`, `lib/`) can trigger a full rebuild and release of every product on push. Put agent tooling where no release workflow watches (often `tools/`), and confirm by checking that no new run started after the push.
- **Path filter for a guard workflow** (scan guards, lint gates: anything that must run whenever a file it reads changes). Write `paths:` as everything minus doc/data suffixes (a `'**'` pattern followed by `'!**/*.md'`, `'!**/*.png'`, ... exclusions), not as a list of code suffixes and directories: extensionless launchers and scripts, and systemd units and timers, fall through a suffix list. Pin it with a test that enumerates the files each guard actually reads and asserts that every one matches the filter; prove the pin red against the old filter. Run that pin test in the guard workflow itself, with the workflow's own file inside its filter: a sibling test workflow's path filter usually doesn't include this workflow's YAML, so an edit to the filter would otherwise run its pin nowhere.
- **unittest discovery.** For tests added to a stdlib `unittest discover` directory, verify actual discovery as well as imports: installing pytest fixes an import error but does not make unittest execute function-style parametrized tests. Preserve every scenario when porting fixtures to unittest and add a collection-count regression; run the exact CI command on each Python matrix version without undeclared packages.
- **Cross-repository integration tests.** Wire every required environment path into the actual CI suite step, not only a local test command. An existing companion checkout does not export its paths automatically. Retain real-producer tests and add a workflow regression tying the export to that checkout before the test runner; verify the green branch run rather than replacing the producer with a mock or skip.
- **Timers and chained runs on a non-default branch.** GitHub fires `schedule:` and `workflow_run:` only from the workflow file on the default branch (`gh api repos/<o>/<r> --jq .default_branch`). Added to a workflow that lives only on another branch, either trigger never fires and reports nothing. Drive that branch's periodic or follow-on runs from a default-branch workflow or a hub cron, and confirm the first run actually started.
- **Shard counts.** Match full-suite shard counts to the reusable workflow's timeout envelope. Reducing an eight-shard matrix to two while retaining the same per-job timeout can cancel every Python job even when e2e is green. Keep the gate's required exact job names, workflow matrix, and test fake synchronized; never count cancelled shards as green or compensate by weakening assertions.

## Known failure classes

- **JS fixtures: `listen EINVAL`, then a timeout.** Keep TMPDIR roots short (for example `/tmp/wc.XXXXXX`): nesting a `RUNNER_TEMP/workspace-checks.*` root under Vitest plus gateway control sockets can exceed AF_UNIX path limits and surface as `listen EINVAL` followed by a timeout. Exercise a real nested Unix socket, executable helper, original failure status, and cleanup through the actual workflow shell. Container `sudo` does not prove mount permission; inspect mount failure and `/dev/shm` noexec/capacity. Reconcile runner label migration before changing retired container hosts; the next real job must prove tmpfs selection and memory reserve on the serving fleet.
- **Detached core-E2E gateway leaks.** Verify `HERMES_E2E_RUN_TMP` survives `coreAppEnv` into the real `gateway ensure` daemon before blaming runner liveness: runtime-variable scrubbing must preserve the lifecycle marker. Exercise both SIGKILL → next-runner recovery and normal exit through the real fixture environment; a marked `sleep` child bypasses this boundary. Pre-fix unmarked daemons require a one-off HOME/HERMES_HOME/argv/owner-verified cleanup; their removal is not post-fix live prevention proof.
- **Hermes E2E failures on loaded runners.** Audit sandbox daemon ownership before raising timeouts. `hermes -z` and viewer `/exit` deliberately retain the shared gateway: each isolated test home must stop its own home/PID/start-time-verified gateway before closing fake provider/proxy servers. Assert viewer-only cleanup first, then full runtime cleanup; never hide arbitrary children as persistent infrastructure. A cold public model-metadata fetch can also reach OpenRouter during another provider's test: seed metadata for the fake model rather than broadening the foreign-provider egress allowlist. For recording/prebuilt TUI probes, pass the installed Node explicitly with supported `HERMES_NODE` through the hermetic child's overrides; obsolete `HERMES_SKIP_NODE_BOOTSTRAP` has no reader, and Node on PATH alone still falls through to `pm.ensure('node')`. Prove attach-only isolation by forbidding PM acquisition in a real child CLI while retaining exact handoff/lease assertions, rather than raising its timeout.
- **Docker: image pushed, then `exporting to GitHub Actions Cache` fails** (`error writing layer blob: not_found`). Keep cache exports advisory with `ignore-error=true` in each `cache-to: type=gha` option list, including release and sibling image workflows. Do not use step-level `continue-on-error`: image build/load/push failures must remain fatal. Test the parsed workflow exporter policy and verify a green main push run; a later artifact-quota warning alone does not establish why the cache backend failed.
- **gitleaks install fails with "Destination file path ... already exists" on a self-hosted runner.** Self-hosted runners keep files between jobs. `gitleaks/gitleaks-action@v2` downloads to the fixed path `os.tmpdir()/gitleaks.tmp`, so one interrupted run makes every later install fail on that runner. Fix in the workflow, not on the hosts: set `TMPDIR: ${{ runner.temp }}` in the step's `env` (emptied per job). Check every runner's failure first (`runner_name` per job) to tell a systemic cause from one dirty host.
