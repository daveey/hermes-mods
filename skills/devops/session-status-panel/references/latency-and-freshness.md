# Panel latency, producer contention and staleness diagnosis

## Diagnose a stale panel (board and panel disagree)

1. Read feed timing on the host (no Desktop token needed): `~/.hermes/session-panel/timing-feed-<role>-<profile>.json`, rewritten after every pass: `tick_started_at`, `tick_duration_s`, `producer_s`, `producer_chats`, and `recent` (last 32 pushes: `rev`, `at`, `sessions`, `pass_started_at`). Freshness of one write is the `recent` entry naming its chat minus the write's commit time; `/status` and `/changes` return 401 from a hub shell.
2. Read the last published models from `feed-<role>-<profile>.json` in the same dir. It is two JSON lines (header, then body): `json.loads(text.splitlines()[1])`, not `json.load` (fails with "Extra data"). The chat's model is `bundles[<session>].bundle.model` (`sections`, `header`), with `bundle.computed_at` and `bundle.tasks`/`cards`.
3. "Panel says nothing running / no dependency shown" while the board says otherwise: compare the card's claim/link/park event times with the painted push's `pass_started_at` before suspecting the reducer. Whole-feed passes can take minutes, so a correct reducer paints a snapshot from before the transition. If the current snapshot is right, the fault is producer freshness, not classification.
4. A remote parent (a card on a worker board) is absent from local `tasks`; `hermes kanban show <id>` says "no such task". Its status lives in hub `kanban_sync_remote_parents` (and `kanban_move_parent_results`, `task_chat_links`): query those directly instead of scanning every board DB (that scan timed out).

## Producer design rules

- Treat ceiling chat count as a work bound, not a latency bound. Preserve a real-loop slow-producer regression plus an event-blocked producer while an unrelated write publishes; fast fakes alone hide head-of-line blocking. When isolating canonical ceiling work, test same-owner/ancestor claims, hot handover, forgotten completions, finite asynchronous retries and wake clear/drain races. Retain other-chat producer obligations when an in-flight stamp read consumes a concurrent outcome write; do not blindly re-admit the producer's own completed writes.

- Test sync-bookkeeping invalidation with real replica SQL and canonical projection adapters. A `pulled_at`-only commit must carry `synced_at` without renewing `computed_at`/execution evidence or hydrating every chat. Admit board-shadow writes even without a hub/ledger write. Canonical hub rows may lack `source='replica'`, and selection may add `source='origin-obligation'`: match observation producer plus owner/profile/board/card/session, not a raw source label or bare card ID. Keep true stale/status/receipt changes semantic, allow legitimate clock regression on source reset, and exercise a real concurrent producer publishing an older capture after a newer observation.
- When moving reconciliation out of presentation, admit producer work independently of outcome/request invalidation: session membership can change without either changing. Exclude the producer's own action-store writes, capture source stamps before writes, and propagate canonical deferred/partial results rather than treating a normal return as success. Keep failure retries bounded and preserve the event cursor. A globally source-gated producer is only an intermediate seam, not per-session batching acceptance.
- When widening per-lineage readers to a whole-feed union, bind owner scopes as one JSON parameter with `json_each`, not two SQL variables per owner. Prove the union at SQLite's 999-variable limit, preserve per-lineage order/profile fences and missing-own-session errors, and deep-copy shared parent presentation. A closed ActionStore snapshot alone does not prove core-board batching or selective source reconciliation.
- Prefer one short-lived read-only connection per source DB per producer pass, with set-based reads for all relevant sessions/cards; fetch results and close before Python processing. Do not introduce persistent reader connections as a latency optimization. Cache board projections until their source changes and make producer wakeups change-driven.
- Keep the scoped source producer no weaker than "any source write admits every chat": the source stamp is captured before the board/external reads, so admit chats those reads marked dirty even when the stamp had not moved, re-admit `_reconcile_deferred` on any moved stamp, and compare lineage with the one last reconciled under (the held bundle may already have adopted the new one).
- Preserve canonical time/courier liveness when admitting source reconciliation per chat: track each chat's last actual producer call, not its last unaffected-stamp settlement. On a real source write, re-admit chats past the canonical mirror's 60 s safety ceiling; this is not an idle polling timer. Exercise a remote answer left `remote-retiring`, let stable-refusal time elapse without moving request stamps, then deliver unrelated writes and assert final retirement plus a replacement ask. Input keys alone cannot represent courier receipts or unkeyed mirror fallbacks.
- Measure the authenticated Desktop listener separately from the always-on proxy. Retain process birth identity, summed per-thread context-switch deltas and process CPU alongside route latency. A warm hub-local `/changes` response below 500 ms does not prove installed Desktop click-to-render, cold hydration or restart recovery. Preserve raw samples and label those acceptance gaps explicitly.
