# Waiting-row legibility

David's content rule for waiting rows: each row answers what it waits on and for how long, nothing else inline. Show the blocker's kind (CI, PR, card, deploy, timer, agent, you), its exact target (repo + PR/run number, or card title), that blocker's own status and numbers (check counts, state age), and the dependency chain to the final blocker. Machine prose ("status unknown · last known: …", "asks origin: …", Pacific timestamps, "on hub", per-row panel-data age) is noise on the row: move it to the tooltip/Details and state freshness once in the header. Put the wait age in a right-aligned column so ages scan down the list.

## Correct a misleading wait explanation

1. Read the exact card's recorded disposition and the exact session's persisted panel row. Distinguish a pending producer or decision from stopped work kept only as evidence; a triage status alone does not establish a wait.
2. If the user asks for clearer card wording, use the supported owner-local `hermes kanban edit-text --request-file <request.json> <card>` CAS operation. Put the current plain disposition first, retain the original specification under a historical heading, and read back title/body plus unchanged lifecycle and human-request fields. A description edit does not change the separately generated panel detail.
3. Trace generated wording through hydrated receipt → reducer → renderer. Prefer qualified retained-stop evidence over spend-escalation prose; preserve current human asks and newer execution evidence. On client expiry, retain the disposition only as historical information without claiming fresh execution status. For a presentation-only correction on explicitly withdrawn work, do not change lifecycle, remove retained evidence or reopen its tests to improve the display.
4. After normal deployment/reload, re-read this session's naturally persisted panel model and check the actual detail, not just canonical session status or sidebar `exact_paint`. Report native pixels as unobserved when only persisted model data was verified; sidebar success can coexist with incorrect task-panel wording.

## Elapsed-time layout

For a missing elapsed timer, inspect the exact session's persisted input and reduced row before changing CSS: distinguish dependency-wait (`parked`) from worker-queue (`queued`), then check `wait.waiting_since` and output `clock_text`. If both are absent, trace the reader's status selection and wait-description handling; dependency wording can be reconstructed independently of timing metadata. Reproduce through the real reader→reducer path with the affected status, then compare an otherwise-identical input with a timestamp. Tests that inject `waiting_since` prove formatting, not that production supplies it. Derive dependency-wait age from semantic lifecycle events and current gating parents; leave incomplete history undated rather than substituting creation, comment or read time. Exercise episode resets, duplicate observations, recovery and nested waits through the real reader, and assert that clock ticks alone do not change the model revision. Persisted model evidence does not establish which revision is currently painted in native pixels.

Once elapsed text exists in the model, keep actor, cause and triage age readable together. An ellipsized detail capped to a percentage can hide a trailing elapsed suffix even when DOM text is correct. Exercise actual Chromium text bounds at 1100/700/420px with long nested-row copy. Let detail wrap below the compact title rather than adding a second parser or clock. Verify the numeric age in native pixels after deployment.

Apply the same geometry check to running metadata: `flex:none` plus `white-space:nowrap` can push the elapsed suffix beyond the panel's clipping ancestor without losing any DOM text. Exercise the real reducer's wire templates through the actual renderer, including long machine/model names, snapshot replacement, remount and local ticks. Keep CI/deploy/timer normal, overdue and missing-estimate controls beside the elapsed regression; a formatter pass is not visibility proof. `desktop-plugins/session-panel/timing.browser.test.mjs` supplies the owned Chromium loop, while the mounted `test/hub-model.test.mjs` guards timing persistence and wrapping in the public Desktop workflow.
