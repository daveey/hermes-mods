# Cold interactive decision admission

Test isolated decision admission through a cold hot-mounted router as well as a warmed one. Concurrent recovery dependencies must await one shielded task per home/event loop, not fill the decision pool with workers waiting on the same recovery lock. Exercise a real decision POST while recovery exceeds the queue deadline; warm-only saturation tests miss this path.

A bounded admission refusal needs an explicit never-started contract and a same-frozen-key Retry path. Generic 503, transport uncertainty and failed receipt GETs must never authorize a repost. Clear a stored retry permission before submitting the identical payload; a lost retry response returns to unknown delivery, not another allowed send. Verify reload persistence and negative cases through the actual renderer.

Failed interactive canonical refreshes must arm the existing bounded decision retry and remain unvouched until recovery, rather than wait silently for an unrelated write. Assert the due time, beat-to-lane wake and successful retry without renewing board/execution clocks. Order availability flags as well as successful component payloads: an older success must not clear a newer failure, and an older failure must not invalidate a newer success. Exercise both interactive/sweep arrival orders. Spending one chat's retry must preserve other eligible chats' earliest due time, including after the first chat exhausts its budget; never replace their armed timer with None or a later backoff. Settle availability, budget and deadline together for each accepted sequence/lineage-fenced result in both lanes, not once using a sweep's captured membership. A chat can be watched and fail while that sweep is blocked; test real-thread membership growth and require its newer timer/budget survive. An accepted successful read resets only its own exhausted budget; exercise exhausted → success → new failure alongside another chat's pending retry, and reject stale success before any reset.

Use the native IPC error envelope in renderer tests. Electron can produce `Error invoking remote method 'hermes:api': Error: 503: ...`; stripping only the outer prefix leaves `Error: ` and fails an anchored status matcher. Normalize only known wrappers, then require the exact never-started POST marker; do not loosen recognition to any message containing 503 or an owner GET error.
