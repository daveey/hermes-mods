# Native acceptance proof

Read before capturing or judging native (installed Desktop) proof for the panel: remote answers, empty/missing-model states, disposable asks, pending/answered decision captures, and verifier placement.

- Prove remote answers through real authenticated HTTPS source-proof and owner-receipt reads, not only an offline composed courier. A native recorded operation can remain pending because the edge rejects Python urllib's default User-Agent even though the enrolled credential works through the courier client. Diagnose the exact frozen request with a read-only application-User-Agent control; retain HTTPS/no-redirect/authentication fences and route repairs through normal independent review. Preserve the original operation/idempotency key and scratch session until its owner outcome is known; never create a replacement click to hide unknown delivery.
- For zero-work native acceptance, require both a zero-count authoritative model and absence of the painted panel/pending placeholder. A null renderer cache plus “Hub status model not available yet” is an availability failure, not proof the empty-panel fix works. Save the exact scoped feed response alongside the settled native capture; do not inject that model into the renderer to manufacture a pass.
- For native missing-model fallback proof, preserve the raw bundle task's absent `run_model`, its hydrated `cards[id].detail.events` route/tier model, and the same scoped rendered running row. A model label in pixels alone does not establish which source supplied it. For emoji proof, retain the exact raw title containing the offending codepoint and compare its corresponding model/DOM title and native PNG.
- Re-test a model-unavailable capture through a fresh owned window and normal hydration before calling the empty-state failure persistent. Preserve the earlier failure, but if the same zero-count revision reaches the native cache and the panel disappears without injection, report recovered acceptance separately from the earlier availability fault.
- For an authorized real native disposable ask, initialize and verify the stored session row before seeding its ActionStore request: `session.create` is lazy, and canonical reconciliation correctly withdraws a request whose chat is not yet durable. After `openSession`, independently require exact focused ephemeral/stored IDs before composer submission; hydration returning is not the focus postcondition. Do not mistake an auto-delivery owner-wait (closed live chat) for a hard delivery error merely because internal `dispatchState` is `failed`; preserve its `ownerWaits`/error semantics when reporting recovery coverage.
- Capture the operation and scoped model in the same native evidence record. A compact pending line painted only after the operation is already delivered proves formatting, not timely pending behavior; preserve the earlier busy capture if it still showed the verbose companion. Slow whole-feed sweeps can make a correct reducer miss the entire pending interval. Use a useful authorized diagnostic turn for real busy-state proof; do not repeat or replace a sleep that a runtime guard refused.
- Real answered asks may already be delivered by verification time. Read their operation dispatchState and report delivered-state dedup separately from the undelivered one-line status and failure-recovery branches; do not create or answer an unrelated ask just to obtain pixels.
- Before assigning native acceptance to a downstream verifier, read its parent edges: if it waits on implementation completion, it cannot supply the proof that implementation needs to finish. Create or reuse a Mac-capable parallel owner with no implementation-completion dependency, then make the final independent verifier depend on both. Read back both execution states and the verifier’s parents; a linked TODO card is not active evidence collection. Keep original acceptance intact and report source delivery separately from native proof.
