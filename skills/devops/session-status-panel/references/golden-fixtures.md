# Golden-fixture recipe

For canonical-header/row disagreements, compose the real core `refresh_outcome` in a disposable stored chat through the real panel reducer and mounted renderer; handcrafted canonical envelopes cannot catch an adapter that admits stale/partial card status. Include retained terminal rows and stale/partial mirrored human asks with a known-current-human positive control: trust checks must precede both terminal filtering and human ownership, including unused mirror fallback. Preserve independent active-local-turn precedence and require reason-aware unresolved labels.

Public structural cases live in `plugins/session-panel/tests/test_model.py`; `desktop-plugins/session-panel/test/hub-model-fixtures.py` serializes the **real reducer** into `hub-model.test.mjs`. Extend both sides, not a hand-built JavaScript imitation of PanelModel.

Shared blocker groups must apply the same owner-qualified canonical request retirement precedence as ordinary rows before consulting preserved `human_request`/`wait_state=human`. Test dismissed, answered and withdrawn requests plus a live-open positive control through the real reducer and renderer; an off-list parent must never turn red again after its ask retires. Run the compatible-core panel suite as well as no-core CI: no-core skips can hide stale real-core triage assertions. Give shared-group fixtures nested DOM assertions rather than applying the flat-row golden count contract.

## Per-card fields

A per-card fact (a count, a run property) belongs in `dashboard/plugin_api.py:_detail` as a key of `detail['task']`. It is the single card-detail producer (board capture calls it too), and `reduce_panel` merges `cards[id].detail.task` under each row; core's session-task rows carry only `_TASK_FIELDS`, so adding the field there needs a core change. Guard the SQL with `except sqlite3.Error` -> `None` (unreadable, not zero) and render nothing for missing/None/non-int. Test both ends: `tests/test_core_readers.py` (`r.card(id, 'default')['detail']['task'][field]` on a real board with `task_runs` rows) and a `test_model.py` case whose bundle carries hydrated `cards={id: {'detail': {'task': {...}}}}`. A detail-only append needs no Desktop change: the renderer prints `detail` verbatim. Before inheriting an id-keyed detail or its event reason, reject contradictory gateway/board/profile coordinates while preserving the serving gateway's authenticated aliases. Test a list row with no `wait` against another owner's real hydrated detail; a fixture that supplies an explicit empty or alternate `wait` masks the inheritance leak. Keep owner-scoped event-history assertions as well as row-field assertions.

Done rows are the exception: `Feed.compute` hydrates cards only by walking from open linked rows and stops at terminal status, so `bundle['done']` rows never get `cards[id]`. Attach a done-row field to the row itself in both producers: `CoreReaders.done` (copy rows; core's listed rows can be memoized) and `board_capture.capture_local` for refreshed rows (the snapshot path never calls `done`). Per-run cost data: tokens come from each run's newest `worker_result` event `usage` (`cost_usd` is present only on some runs); the model is that run_id's `run_route` event. `agent.usage_pricing.estimate_usage_cost` returns `included` for `openai-codex` and `unknown` for `xai-oauth`: price those at `openai`/`xai` list rates. Class-routed runs record `class:*` and have no priceable model: say so, never a guessed figure. Done-row wording: the section already says done, so `test_model_audit.py` rejects a `done` word in a row; a completion time is a bare wire `ago` clock part (`3 h ago · 42m · …`) built from the row's own `completed_at`, and exact-string done-row tests in `test_done_run_stats.py`/`test_model_audit.py` must change with any new prefix.

## Running the suites

Through `terminal`, run:

```sh
python3 scripts/test-all --no-core --exact -k plugins/session-panel -k plugins/ask-gate -k plugins/user-steps
python3 scripts/test-all --no-core --exact -k repo-guards
node --experimental-strip-types --test desktop-plugins/session-panel/test/hub-model.test.mjs
```

The Node test resolves `react`, `react-dom` and `jsdom` from `HERMES_DESKTOP_DIR` (default core `apps/desktop`). On a host where that has no `node_modules` ("Cannot find module 'react'"), write a bare `package.json` into a scratch dir with `write_file`, `npm i --prefix <dir> react@19 react-dom@19 jsdom`, and run with `HERMES_DESKTOP_DIR=<dir>`. Run `node --test` on the test file; on the `test/` directory it reports a single opaque failure. Prove a regression RED by restoring `origin/main`'s `plugin.js` (save `git diff` first), running only the new case with `--test-name-pattern`, then `git apply` the saved diff.

For a quick core-backed run of the panel tests on the hub, use core's venv: `~/.hermes/hermes-agent/.venv/bin/python -m pytest -q -p no:cacheprovider -n 8 plugins/session-panel/tests/` with a 400 s timeout (`hermes-core-python` has no pytest; serially the ~940 tests overrun the default 180 s terminal timeout). Under `pytest -n`, `test_fact_transport.py::test_host_large_reset_recovers_panel_without_resubscription_loop` fails with `AF_UNIX path too long` (xdist's deeper tmp path); rerun it alone before treating it as a regression.

When pinning core for `scripts/test-all`, pass `--hermes-core <isolated checkout>` (or `HERMES_CORE_CHECKOUT`) and verify the emitted core path in `--json` results; setting `HERMES_CORE_SOURCE` alone does not select the runner's checkout. Before the Node command, provision dependencies exactly as `.github/workflows/desktop-plugin-tests.yml` specifies. For full core-backed coverage set `HERMES_CORE_SOURCE` to an isolated compatible core checkout, `HERMES_DESKTOP_DIR`/`HERMES_DESKTOP_PACKAGE` to its installed test dependencies, and make nanostores resolvable from that core. Run serially and require zero core-dependent skips before claiming full coverage. No backend `plugins/session-tasks` suite exists; its tests are Desktop tests. `scripts/test-all` has no `desktop-plugins/*` suite (`-k desktop-plugins/...` exits 2, "no such suite") and the pre-push hook does not run them: run the `node --test --test-concurrency=1` glob yourself before pushing any `desktop-plugins` change. Run all `desktop-plugins/*/test/*.mjs` when changing shared rendering/answer integration.

Any change to reducer row text (`detail`, `clock_text`) also changes the cross-surface P0 golden `plugins/session-panel/tests/session_state_v2_goldens.json`. `test_real_feed_model_goldens` is core-backed, so it runs only in plugin-suites CI, and a text change committed without regenerating the golden turns main and every branch red. Regenerate it in the same commit: `HERMES_CORE_SOURCE=<core main clone> <python with core deps> plugins/session-panel/tests/session_state_v2_fixtures.py > /tmp/actual.json`. Then rewrite the golden as `json.dumps(obj, indent=2, sort_keys=True) + '\n'` and check the diff holds only the intended text plus `revision`. When a PR's only red check is this test and the PR doesn't touch the reducer, run `gh run list --branch main --workflow plugin-suites` before rerunning. If main is red too, fix the golden on main in its own PR; don't rerun yours.

For a private historical golden, retain raw input, observation time, source revision and expected output in private task attachments. Pin `now` and source clocks to the recorded snapshot; distinguish historical replay from current production. Never publish personal/employer/network details or normalize source identifiers/timestamps just to make a replay pass. Include local, remote, triage, C/A ordering, stale human block kind, retired requests, canonical header and consent boundaries. Inspect every resulting assertion and test exit code; missing dependencies or a timeout are not behavioral proof.
