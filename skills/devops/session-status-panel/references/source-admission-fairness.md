# Independent source admission and fair service

An independent task-refresh lane must admit external hub/origin-ledger/replica writes as well as local board revisions: a file-watch wake alone proves nothing if unchanged board stamps skip capture. Exercise an external-only semantic change while the full sweep is blocked, and real adapter observation-only pulls without hydration or renewed execution clocks.

When adding a lane capacity-service thread, run the genuine predecessor `feed` and `_run_board` entry functions against the current Feed/BoardLane in two distinct controls: natural reload with NO current API call, and explicit current-entry repair. A passing repair control does not establish natural activation: saved predecessor restart can be the only entry executed while push traffic continues. Require service establishment by the registered capture owner without later traffic, keep manually driven lanes inert, and verify the actual live `_serve` thread rather than inferring activation from a successful reload receipt. A live coordinator does not prove its service thread was started: older saved restart closures can instantiate current classes without invoking newly added startup methods. Require idempotent service establishment and behaviorally prove two admitted chats refill a single slot while recapture stays blocked; retain a current-entry control. Pause the genuine predecessor thread before constructor registration as well as after it: a one-time current-API lookup misses a not-yet-registered lane. Publish the service requirement and register the lane under one shared lock so either ordering establishes service without a later request; assert stopped/closed lanes cannot start or resurrect it.

Separate completion-driven slot refill from synchronous source recapture: a capture blocked in the owner-qualified external adapter must not hold already-admitted chats or completed workers. Keep one cursor owner and the existing capacity/FIFO/retry fences. Exercise the genuine predecessor feed entry plus current API repair after hot reload; a new loop starting the service is insufficient when an older saved closure still owns capture.

Keep failed strict-capture custody separate from per-chat hydration success. Admit a local read, pause it after reading rows, fail the later external capture, then finish the read and execute a real heartbeat: the held chats must remain absent from `fresh` until successful recapture. Preserve the fence across full hydration and in-process resume; clear it on forgotten membership, and let successful recapture clear only capture custody, never unrelated hydration/decision failures. Test unchanged-source recovery as well as a new source event: otherwise a combined failure flag can either be erased by the earlier worker or leave unaffected chats permanently unvouched.

When a main rebase expands producer admission while a composed owner extracts that block into a shared helper, preserve due trailing/safety and budget-carry scopes in the helper as well as the legacy early-return check. Exercise real composed ticks for no-new-write carry drain and fixed-deadline trailing/safety admission; retain main's producer budget/floor/expiry methods and existing tests. Drain asynchronous initial acquisitions before asserting quiet admission, and use actual changed local inputs rather than an unrelated synthetic source stamp.

Compute reader-role renewal identity from current immutable exact ScopeDemands as well as source and membership. After initial+3 factory failures, test recovered local AND external roles with demand-only expansion while files/membership remain unchanged, paired with a real source-write control; otherwise a valid new dependency can stay unknown forever behind an exhausted role. Retain unchanged peers' per-source budgets.

Isolate `HERMES_HUB_STATE` in real CoreReaders scheduler fixtures: `hub_db_path()` follows that setting or `Path.home()`, not disposable `HERMES_HOME`. A worker's live replica writes can legitimately renew an allegedly unchanged external source and intermittently invalidate retry-exhaustion assertions. Trace actual stamp tuples before freezing clocks or changing production retry semantics.

Compute service wake deadlines from effective source AND reader-role eligibility. A due source timer behind a future role backoff must wait for that role; an exhausted role must suppress the obsolete deadline entirely. Test the actual service with a strict-capture failure followed by a reader-factory failure, frozen exact source stamps, a bounded spin counter, and exhausted-role control. Enforce the same projection retry budget in queueing and dispatch for full/catch-up reads: settle unavailable tickets explicitly rather than hanging or launching extra attempts. Prove both future backoff and exhaustion, then show a genuinely changed acquired source renews only the relevant budget.

Assert returned full-route values as well as stored publication after canonical races. A writer may merge a newer canonical component into an older board candidate; returning the candidate can expose retired consent even when the stored panel is correct. Pause a real canonical read before request withdrawal/approval/deleted-session retirement, then require the returned bundle to preserve the actual writer-merged current authority.

For compatible stopped-owner transfer, rebind immutable snapshot dataclass keys into the current content-qualified module; identical field layouts do not imply Python class/key equality. Test transfer with two independently loaded snapshot modules, exact watch/demand/receipt identities and rotated acquisition tokens; reject changed layouts before consuming the old store. Preserve retry signatures/counts/deadlines independently of reader objects. Keep projection ages through failed-attempt backoff and exhaustion, not only while pending or active. Join a completed projection without servicing its completion queue, then reload: a finished slot can remain in `active` after its retry entry was removed, so inheriting every active key can recreate served work and crash dispatch. Test that boundary, unchanged exhausted source/role/projection budgets, and a failed candidate's recovery without consuming transfer custody.

Bound service priority separately from payload coalescing: preserve the first unserved admission time and use oldest-first/bounded-aging scheduling. A continually rewritten newest-first queue can starve a quiet changed chat despite bounded memory. Test saturated capacity with continuing newer arrivals.

Distinguish served pre-pin requeues from genuinely owed post-pin requests with a local worker-generation fence, never replacement source authority. Clear successful episode ages only when the immutable admission/current canonical base covers the request; evaluate failure clearing after removing served pending work. Barrier-test both sides of the pin. After a successful retry, retained same-signature post-pin work must remain dispatchable: count>0 with retry_at=None otherwise means permanently in-flight. Re-arm that existing finite budget without resetting its count/age. Apply the same consumed-attempt backoff to a retired in-flight projection during compatible transfer, while leaving truly exhausted and already-finished slots untouched. A reload regression must establish the current service only after predecessor drain; asserting fields on PendingSourceOwner proves fixture setup failure, not behavioral RED.

Treat a capacity-service activation as a rollout seam, not a latency fix: serial strict external capture can still delay admission, and bounded per-chat hydration can still saturate the queue. Measure capture/source-to-admission separately, then prefer source-changed, set-based shared snapshots over repeatedly reading every chat's complete card chain. Do not increase concurrency to conceal duplicate work or waive whole-process CPU accounting.

Measure admission-to-publication as well as reader-start-to-publication; a passing reader p95 can hide a failing queue. Exercise completion-driven slot refill while the NEXT strict external capture is event-blocked, not only while another hydration worker blocks. A synchronous recapture before draining completions can leave finished workers occupying bounded slots for entire capture passes. Preserve the failed live interval and process/path provenance; a timing-writer PID is not necessarily the executing worker PID during hot reload.

Test newly landed admission routes through the composed owner, not only the legacy Feed. Include `queue_keyed`/`refresh_keyed` in the real all-route materialization test and execute the actual file watcher's periodic recovery branch: a missing owner seam can throw outside the hint branch's fallback and terminate the watcher. Record pending keys only after owner admission succeeds; preserve first-unserved ages and exhausted retry budgets.

Exercise keyed admission concurrently with projection base selection, not just sequential all-route calls. Feed-held keyed admission enters the coordinator; a projection must not hold the coordinator lock while taking Feed.lock in the opposite direction. Preserve exact watched membership and pending-after-success, snapshot base candidates under separate locks, and retain the original pin owner's Feed watch token through publication. Barrier-test both forget and forget/re-watch during base selection: a fresh same-name Feed token captured after the old store pin can otherwise authorize an obsolete projection. Use a bounded lock adapter only to unwind a failing test safely, and join all probe threads.

Measure private receipt instrumentation at the full shared-scope population before treating a disposable contention harness as performance evidence. Repeated whole-store snapshots and recursively re-detached shared certificates can dominate acquisition or exceed bounded audit resources even when SQL is fast. Preserve the failing trace, keep mandatory admission/source/writer joins, and prove any per-traversal memo emits identical JSON and still rejects nested mutable aliases; never cache validation across captures. A queued projection can observe a newly committed source before its `source_received`/`admitted` receipts are recorded: barrier-test that ordering through the actual coordinator, including already-running contenders, rather than weakening the strict auditor.

Separate deliberate strict-capture barriers from acquisition performance budgets in saturated service-order fixtures. Give only the capture module a fixture-owned monotonic clock (copy all other time functions, including `time_ns`), retaining real scheduler clocks and actual publications. Bound each completion handoff without sleeps or retries; require all 64 publications, FIFO/coalesced queue ages and the two-slot bound before releasing strict capture. A wall-time budget expiring while the fixture intentionally blocks can invalidate every projection and imitate starvation. Keep acquisition latency/CPU acceptance separate and unchanged.

Test sync-bookkeeping invalidation with real replica SQL and canonical projection adapters. A `pulled_at`-only commit must carry `synced_at` without renewing `computed_at`/execution evidence or hydrating every chat. Admit board-shadow writes even without a hub/ledger write. Canonical hub rows may lack `source='replica'`, and selection may add `source='origin-obligation'`: match observation producer plus owner/profile/board/card/session, not a raw source label or bare card ID. Keep true stale/status/receipt changes semantic, allow legitimate clock regression on source reset, and exercise a real concurrent producer publishing an older capture after a newer observation.
