# Opted-in source-owner lifetime

Freeze both the older saved entry point and the older coordinator implementation in reload tests. An old closure around today's coordinator can conceal a dependency on newly added retire/drained methods. Withdraw the old store's publication authority before joining workers. Keep successor role capacity closed until every old acquisition has released its reader and every old projection has completed, including across consecutive reloads. Use barriers, not timing assumptions; preserve the nonactivation boundary.

Defer current reader construction from resume to the existing pending board step. A genuine saved API can hold PROCESS_LOCK during resume, while CoreReaders.snapshot_modules acquires the loader lock; natural reload owns loader then process, so inline construction reverses the order. Exercise actual feed/resume and _load_feed entries with event barriers and a bounded teardown lock, retaining an edge-removal diagnostic control. Keep both saved-entry registration orders/no-traffic publication controls and explicitly drive manual installation before transfer assertions. Migrate every manual resume fixture, including observation provenance, external recovery and exhausted retry budgets; reread the installed owner after the supported ensure call. In manually driven drain helpers, an empty worker/pending set is not quiescence while the board completion wake remains set: consume that wake to admit newly established demands, with a deterministic completion-before-idle-check regression.

A hot feed reload can retain an older API's saved RESTART closure and its old CoreReaders. Ensure new lanes idempotently for an existing current Feed, and give each added lane current-generation readers with explicit release. A new Feed type alone does not prove new reader methods or threads. Test the genuine older entry point, not just a current-class resume.

Compose reload with observation-only publication and changing source inventory. A carried predecessor observation parent is not current Feed/epoch/watch authority and must not veto every fresh same-admission projection; keep the current-owner parent CAS intact. Reconcile inherited source/scope retry attempts against the successor's actual acquisition inventory so removed keys cannot retain expired deadlines with no executor; unchanged keys retain budgets and new keys remain missing. Reconcile successful coverage as well as retry keys: reset inherited sources absent from the successor inventory through the fixed store API, retaining their history only as missing/stale. Test healthy source removal and canonical-path replacement before any acquisition failure, across consecutive reloads and keyed/full publication; a failed-source-only fixture masks authority leakage. Preserve unchanged-source exact versions/budgets, actual new-source acquisition and finite drain. Test healthy/unavailable strict capture at unchanged stamps, real failed source removal, combined finite drain and the unchanged-inventory/parent-CAS controls. Join exact retired worker identities before manual installation instead of assuming a completion message means exit.

Retain role custody until actual worker thread exit, not merely its completion notification: a worker can enqueue completion and remain alive before returning. Hold deterministic post-notification/pre-return barriers for acquisition and projection, including inherited retirement objects whose older `ready()` already says true. Fence current reader candidate construction as well as worker admission, and preserve a bounded autonomous revisit after the final completion wake so a saved board loop establishes the successor without new HTTP traffic.

Retire a served episode's FIFO age atomically with its successful attempt, independently of the still-live worker slot. Barrier the successful worker immediately before completion notification, queue an unrelated chat then a fresh same-chat episode, and assert the unrelated chat retains priority without releasing the active slot. For a real projector failure retried across an observation-only publication-parent CAS, rearm the consumed retry deadline before queue readiness while retaining the finite failure count; test eventual drain with real capture/publication and a no-observation positive control.

Exercise both beat and full routes through the same bounded local-settle failure path in saturated FIFO fixtures. Preserve the exact exception type/message in diagnostics; an assertion on the route name alone hides the cause. Hold a real NEW-write acquisition through the actual deadline with a barrier, then require a successful same-route retry and exact requested chat/content coverage after drain. A documented timeout is a failed call, never a successful route or latency sample; unexpected exceptions still fail the test.

Treat pending reader construction/release as independent lifetime custody across consecutive resumes. Carry every still-installing ancestor before closing its pending handle; the retiring source-role ancestor alone cannot represent it. Barrier both the factory and candidate release, resume two or more generations while held, require no second candidate until release, then exercise the saved pending loop's bounded recovery without HTTP traffic or a waiter thread.

Treat a successfully queried absent session row (deleted chat in Desktop recents) as unknown outcome with no requests. The real user-steps adapter requires the watched session's own stored row to establish ownership and otherwise raises 404. Test real CoreReaders + user-steps + SessionDB + Feed, not only a patched request adapter. Only existing sessions get exact owner/lineage request reads. Unavailable canonical sources must retry and remain unvouched until recovery.
