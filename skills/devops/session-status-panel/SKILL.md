# Session status panel

Compute classification and wording on the backend; render that snapshot on Desktop. For clock-only feed churn, read `references/relative-display-times.md`. The model is not permission to execute a choice. All paths below are relative to the hermes-mods repository; work in an isolated worktree, not its deployment checkout.

## When to Use

- The status panel shows a wrong section, count, title, option or recommendation.
- Add a field to the session panel, or understand how an unblock card renders.
- Verify the same local, remote-gateway and triage ask layout.
- For writing the ask itself, load `generate-unblock-card`; this skill owns the rendering contract.

## Prerequisites

Read [PanelModel v1](../../../plugins/session-panel/MODEL.md), the machine-readable schema and ownership notes. Inspect the current producer and renderer before changing a field: that document includes historical phase notes, not promises that every gateway has the same deployed version. Use `read_file` and `search_files` for source inspection; use `terminal` for the test commands below, from the worktree root.

## Contract and input map

`dashboard/feed.py` publishes `bundle.model` through `POST /api/plugins/session-panel/changes` and `plugin.session-panel.changed`. Desktop caches by connection/profile/session, not session ID alone.

| Output | Authoritative input / transformation |
|---|---|
| `version`, `revision` | `model.py:reduce_panel(bundle, now=...)`; version 1, deterministic SHA-256 of canonical model JSON excluding revision. Not the feed's monotonic `rev`. |
| `header.state`, `header.status`, `header.source` | Validated `outcome_json.status` is preserved unchanged with source `canonical`. Without it, source `derived` and status null distinguish the backend's needs-you > stuck > running > waiting (including Ready) > idle section fallback from the protocol. Row-source read errors retain unknown; missing outcome alone does not. Legacy kind/prose never becomes the status protocol or authorizes green. |
| `sections` | Six arrays: `needs_you`, `stuck`, `running`, `waiting`, `ready`, `done`. Feed `tasks` plus hydrated `cards`, current requests, execution annotations, rentals and confirmed done history feed the pure reducer. |
| `header.counts`, `header.pips` | Unique displayed rows, per section; only nonempty sections produce pips, in section order. |
| Row identity | `id`, owner-qualified `key`, `kind`, `gateway`, `profile`, `board`; retain the exact source coordinates for deduplication and opening. |
| Row text | Backend-authored `title`, `detail`, `details[]` from card and execution evidence. Wire models carry display ages as `clock_text` templates with absolute timestamps; session-panel/session-tasks format them on local timers without HTTP reads. Keep classification and execution freshness server-owned: elapsed display ticks must not change the wire model/revision. Preserve template parts when clipping long text, especially elapsed plus deadline countdown. Suppress parent text only when that same dependency is already visible in the rendered hierarchy; retain flat/hidden and additional parents. Never suppress the row's own status. |
| Ask content | `source`, `situation`, `options[]`, `only_you`, `recommend_letter`, `reason` from `human_request` via `brief.py:parse_brief`, or current question-store content. |
| Answer binding | Current request `request_id`, `request_revision`; each option's `choice_id`; `decide` action carries the exact request owner. No guessed IDs or index-based binding. |
| Other actions | `open_card.target={id,gateway,profile,board}`. Action labels are display data, not commands. |
| `diagnostics` | `input_errors` distinguish unavailable sources from a known empty source. `computed_at`/explicit `now` fix the read clock. |

`inputs.py` reads current lifecycle/resolution from the action store, not the frozen revision's old state. It invokes user-steps mirror reconciliation through the reader and starts the shared rental refresh. The reducer itself performs no I/O, migrations, reconciliation, decisions or implicit clock reads.

Classification details live in MODEL.md and `model.py`, not a second implementation here. In particular: preserved `block_kind` alone is not a live human wait; stale remote reports do not prove completion or running; unresolved execution evidence is explicit unknown Waiting; retired requests never reopen a decision. Subagents/processes require canonical execution evidence. Rentals are owner-filtered rows. Confirmed done history is owner-qualified and deduplicated.

## How a brief becomes tiles

The shared parser is [brief.py](../../../plugins/session-panel/brief.py). Ask-gate's `unblock_card_quality.py` uses its raw `sections()` and `options()` grammar; `parse_brief()` adds presentation. Acceptance and display share parsing, but display does not replace quality validation.

1. Write `Situation:`, `Options:` and `Recommend:` on separate lines in `human_request.scope`. Use `A) Short name: consequence; cost; reversibility` per option. Prefer this canonical form even though the parser tolerates headings, bullets and some inline labels. Machine-contract lines (`DEVICE:`, `HUMAN_STEP:`, `OBSERVATION:`, `EVIDENCE:`) terminate a parsed part; preserve contract scopes exactly.
2. `choices[].label` controls tile order **and the displayed name** when choices exist. Use `C: Test live (recommended)`, not an opaque label. Unique own letters are preserved, including C/A ordering; missing/duplicate letters or insufficient room for Skip/Other use positional badges. Scope details join by letter, never list index. Without choices, the scope option's short name supplies the tile name.
3. A scope recommendation wins; keep `Recommend: C - reason` consistent with the single recommended choice. Only if no recommendation part exists does a unique recommended choice supply the letter. Keep its reason in the first paragraph: appended evidence/footer must not become recommendation copy.
4. `why_human = Tried: ... Only you can: ...` yields a visible `only_you` line and a folded tried trail. Put decision-critical consequences in the brief, not only in `action` or evidence.
5. `model.py:ask` adds request/choice bindings and consent details (plan, limits including permission flags, exclusions, outcomes, choice explanations). `desktop-plugins/session-panel/plugin.js` draws the model; session-tasks chips consume the same model. User-steps supplies decision submission, composer integration and pending receipt recovery, not a second set of card tiles.

A bound choice goes through the existing user-steps decision operation, with exact owner, revision and idempotency key. Unmirrored remote asks can retain a composer-draft fallback during a mixed-version rollout: a draft is **not** a recorded choice. Inspect the installed action and binding; never claim the remote answer path works from matching pixels alone. Never fabricate a binding, execute scope text, or replace the fenced decision operation with comment-plus-unblock.

## Add a section or row field

1. Trace the exact focused connection/profile/session to the feed input, then to `reduce_panel`. Reproduce with a pinned input before editing; a model read for a different chat is not a visibility diagnosis.
2. Change the backend input adapter and pure reducer first (a per-card field: `references/golden-fixtures.md` §Per-card fields). Extend MODEL.md's schema, including counts/pips and section ordering for a new section. Decide missing/unknown semantics explicitly. Preserve canonical header/execution ownership, source coordinates, consent boundaries and current request lifecycle.
3. Add a Python regression for the field and negative cases (missing/stale source, duplicate owner IDs, retired request). Assert deterministic revision equality for identical input and a changed revision for changed presentation.
4. Update Desktop's model validation/section list and rendering only after the producer emits the field. Keep presentation fallbacks explicit for older models; do not reintroduce Desktop classification or brief parsing. Update session-tasks' model projection if the chip needs the field.
5. Extend the producer-to-DOM fixture to assert actual text, order, details and exact choice binding. Keep pending Check status/Retry recovery mounted even after a request leaves the visible decision queue. Passing counts alone do not establish preserved behavior.

Completion criterion: one authoritative producer, a documented contract, Python and actual-renderer regression coverage, and no duplicate parser/classifier.

## Live proof

1. Read deployed hermes-mods SHA on the target Mac after normal sync; verify the change is in its ancestry. Read the live plugin version and exact painted connection/profile/session as well: checkout HEAD alone does not prove a backend imported new routes.
   Live proof never gates completion: capture only if a non-inspector preflight (latest `[panel-timing]` line in the Mac's `desktop.log`) shows the needed rows on screen, else report unobserved (kanban-orchestrator `references/human-acceptance.md`).
2. Use read-only DOM/store inspection and native `capturePage()` in the user's existing Desktop. Do not restart it, navigate it, type, open cards or click choices to manufacture proof. If the needed asks are not already visible, use an authorized hidden **owned** probe with disposable home/backend and pinned target identity, or leave native proof unobserved; a browser fixture is not the user's live Desktop.

## Pitfalls and verification

Before claiming BoardLane load reduction, read `references/aggregate-board-load.md` (per-session versus global duty; churn-complete thread measurement).

- For PID-pinned timing windows, verify route/birth identity and retirement journal at both boundaries plus first/last completions. A30min collector can outlive its retired target and read a static file: duration/no errors do not prove coverage. Preserve interrupted cohorts as NO_PROOF, distinct from latency FAIL; zero unchanged samples never prove success. For slow successful memo hits, read `references/memo-hit-latency.md`.
- In live DB-open samplers, trace attachment can precede source-write observation by a warmup interval. Exclude trace opens outside the measured interval (or observe source stamps before attachment), and keep no-history opens unknown rather than inventing a >2 s lag. Report the raw orphan field and the boundary correction separately. A timing file updated only after completed passes is right-censored during a slow pass: retain its eventual completion and distinguish overlapping-pass statistics from completed publications inside the CPU window.

- Match JavaScript safe-integer wire semantics in Python status-envelope validators: JSON round-trips may decode integer-valued numbers as floats, so accept finite, nonnegative integer-valued `int`/`float` values up to `9007199254740991`, but reject booleans, strings, fractions, negative/non-finite and unsafe values. Test real JSON round-trips and all three numeric fields. When testing a missing canonical status, assert the derived header source and null status separately from row text; preserve answered-ask one-line recovery/dedup assertions. Test legacy-envelope rejection separately from canonical backend-authored labels, and run the whole Desktop-plugin glob, not only producer-to-DOM fixtures.

- Keep the user-steps installation owner (`install:<id>`) separate from the courier/sync gateway name. Membership rows and authenticated `gw:<name>` request routes use the latter; ActionStore namespace/operation owner use the former. Derive each from trusted local identity and exercise a producer-to-owner integration with deliberately distinct values. Equal fixture strings conceal a protocol that never mirrors or verifies a real operation.

- The left-pane **Blocked** sidebar section and the red row stripe have different inputs and different owners. Look for the Blocked section in core (`apps/desktop/src/plugins/kanban/blocked-section.tsx`, `fetchBlockedTasks` in `api.ts`), not in hermes-mods `desktop-plugins`. It lists every blocked card on every gateway and board. It groups each card by `managing_session_id` (the latest `tui` notify subscriber), else by the card's `session_id`, and gets group titles from `/session-labels` on the backend's own profile. The stripe turns red only from a visible row's `kanban_blocked`. When the section shows a card but no row is red, check the card's owner session on its home gateway (`home_gateway`; the local replica can be empty, so read the owner's DB through `tailnet_exec`). Cards created by background profiles have sessions the user's chats never show.
- Preserve the original `wait.waiting_on` when deciding whether graph ancestry may replace a wait: `wait_info.raw=''` can mean an exact canonical clock needs no extra Details copy, not that no producer was published. Test future and overdue canonical clocks with fully hydrated unfinished parents, not only `upstream` metadata. Resolve deeper live-source parent coordinates from the serving gateway just like direct dependencies, while leaving unknown replicas unlinked; test both direct and multi-hop chains. Traverse only already-hydrated evidence, bound cycles, and retain explicit primary-producer precedence at every visited intermediate dependency, not just the root. Keep canonical clock countdown/overdue and CI/deploy wording when hydrated owner reasons exist; preserve the full reason in Details rather than erasing the canonical wait.
- Exercise leaf traversal through real CoreReaders hydration, not only hand-built task dictionaries: stored core Task has no `wait` field. Populate canonical wait annotations in the reader for both live and replica details before the pure reducer chooses graph ancestry. A synthetic `task.wait` can make nested clock/CI/deploy precedence tests pass while production opens an unrelated ancestor. Include disposable-board reader-to-reducer controls and assert the exact parent action target as well as its text.
- A card the chat is waiting on is often not linked to that chat (for example, a worker created a review card). It then gets no row of its own, so the waiting row's line must carry that card's live status, not just its title. Otherwise running work looks idle. When the user asks "why isn't that card shown?", check `wait_target` and the hydrated `cards[id]` before you look at session linkage.
- Row UI preference: card/dependency/session opens are the row's right-click menu, never inline links: `references/row-actions.md`.
- Color preference (David's rule): red only when he must act, i.e. a live `human_request` or user-steps ask. A triage/held card needing no human (`scope_stopped`, `decision_retained`, spend hold without `human_request`, creator-decision park) is blue with a plain-words detail naming who acts next ("waiting on this chat's agent to decide: <reason>"), never red or a bare "waiting". A wait on something already producing the result (CI, clock, running card) is light blue `#38bdf8` (row box, waiting pip, header dot), never grey or amber; a wait for a hub deploy (`wait_kind` deploy / `waiting_on` starting `deploy`) is purple `#a371f7` (panel `DEPLOY_COLOR`, session-tasks chip look `deploy`); stalled waits stay amber. The model emits `wait_kind` per row, and on the header and pip only when every waiting row qualifies; the renderer just reads it. The coloured row box draws beside the title even when a live ETA renders: colour carried only by the right-column ETA is off-screen in a wide panel, so the wait reads uncoloured. Renderer tests assert the pip's computed colour for every wait kind × ETA state, never its absence.
- Fix hidden-blocker classes, not one reason code: inventory eligibility/claim/startup outcomes and trace local/replica evidence into the model and renderer. Every unfinished non-running row must explain why and who/what acts next; missing/stale evidence means unknown, not presumed worker contention. Show admission blockers as blocked/stuck without inventing a human ask. Test real producer-to-renderer paths plus recovery and stale-reason clearing: synthetic codes can pass while production never emits them. Keep immediate task recovery separate from the broader reporting fix.
- "The panel asked me the same question twice" means duplicate user-steps requests, not a renderer bug. List the session's requests in the owner's `~/.hermes/user-steps/actions.sqlite3`: `requests` (namespace, id, session, state, resolution) joined to `revisions.body` (JSON title/kind/choices) and `lifecycle` (created_at, withdrawal). Then read `~/.hermes/cache/user-steps/trace.jsonl` for that session around the second request's created_at. An `open_ask_hold` → `publication_buffer verdict=pass attempt=<budget>` with the sentence in `unmapped`, followed by `transform new:[us_…]`, means the reply's prose restatement of a card the producer tool published that turn was minted as a second tile (`core.same_open_ask` maps only exact titles or corroborated repeats). Fix that in user-steps, not in the panel.
- An approval tile showing only "A · Request changes" is a `needs_context` request: an `approve` step extracted from prose with no plan, so user-steps offers only the revise choice. `model.py:ask` emits no options for it. If the work was already answered and done, withdraw the moot request; then file the producer leak as a user-steps card. Withdraw by hand from the user-steps plugin dir with `core.withdraw_request(core.ActionStore(<dir>/actions.sqlite3), core.Ledger(<dir>, None), owner, request_id, by='agent', reason=...)`. Take `owner` from the ledger step's `requestOwner` in `~/.hermes/user-steps/<session>.json`: `core.server_owner()` raises "Server gateway identity ... missing" outside the gateway process.
- Renderer rewrites must keep the header's collapse caret (`data-panel-toggle`, persisted per chat, reopened by new needs_you/stuck keys). The hub-model cutover silently dropped it, and the audit test now asserts it.
- Before changing source-owner reload/lifetime or missing-session behavior, read `references/source-owner-lifetime.md` (genuine older coordinator, reader release, role custody and canonical ownership).
- When a fast lane special-cases a source state (absent session row, 404), run the full sweep on the same state and alternate `tick()` with `refresh_decisions()`: both lanes must yield the same `requests`. `inputs.read` falls back to a direct `actions.sqlite3` read when reconciliation raises, and a deleted chat's requests stay stored, so an empty fast value makes the ask flip every quiet sweep. Seed a real request, then `SessionDB.delete_session`; an empty store hides it.
- A compatible `HERMES_CORE_SOURCE` alone does not execute tests explicitly requiring core `tests.conftest` guards. Run remote-card composed cases through `plugins/user-steps/run-core-integration.sh --remote-card-composed` with an isolated landed core and real landed courier, then validate the hosted JUnit manifest with `composed_results.py`: all nine required cases and all selected cases must PASS with zero skips. Retain exact mods/core/courier SHAs and the job URL; standalone suite green with guarded-case skips is not acceptance.
- Before changing decision lanes or retry, read `references/cold-decision-admission.md` (cold recovery, typed admission refusal and bounded canonical refresh retry).
- Before shared human-attention predicates, read `references/partial-source-attention.md` (panel-local coverage rejection).
- A push heartbeat proves transport freshness, not executor liveness. Do not reinterpret the cached model; test cold legacy caches per `references/latency-and-freshness.md`.
- Before changing header freshness, read `references/last-known-header.md` (historical labels versus current trust and timestamp fences).
- Classify held triage by the current actor and administrative cause, not the generic specification fallback: live human requests are red; owner-agent decisions are blue; canonical live card/CI/deploy/clock producers retain light-blue precedence. Read actual retained/spend/escalation event payloads from hydrated replica details. Show triage age from the latest lifecycle entry episode, never created_at; repeated holds within an episode do not reset it. Test real promotion/escalation formats, shared blockers and dependency labels, and use wire elapsed templates so display ticks do not churn revisions.
- Test observation-only invalidation with real replica SQL and canonical projections: hub/shepherd and origin-ledger rows can omit `source='replica'`, and selection can add `source='origin-obligation'`. Carry known pull clocks separately from semantic inputs without renewing computation/execution clocks. Test shadow-only writes, legitimate clock regression, and an actual older producer publishing concurrently. Exercise `CoreReaders.linked/done` through `session_tasks`, not only a substituted linked adapter; distinguish replica-path proof from full ledger-cache and batching proof.

Keep the historical timeout cause undetermined unless reproduced; loading recovery does not establish a CPU fix or five-second service guarantee.
