# Scope and dependency pitfalls

- For silent triage reports, inspect the original stop, producer-ready event, owner publication envelope and destination transcript separately. A canonical `decision_retained.next_action` naming a chat does not prove a `spend_budget_decision_ready` was emitted or that the replica notice consumer admits triage. Check whether repair is behind stale-age/activity filtering before saying notification machinery is absent. Preserve restricted dependency edges: notifying a waiter must not convert incomplete parent acceptance into success. When tightening creation authority, seed genuine recorded creator/session provenance in compatibility fixtures; never globally monkeypatch the authority check off or strip its argument from subprocess creates to make unrelated tests pass.

## Pitfalls

- For held-card notification latency, run the real unloaded consumer with its default production grace on the first observation; a `grace_s=0` fixture proves delivery but not bounded latency. Keep live-turn and gateway FIFO custody intact when admitting urgent decisions. Verify computed unread from `list_sessions_rich`, not raw session rows.
- For terminal-run reservation across gateways, test the card home with no local probe row: wake checks are machine-local and the authenticated park identifies the remote probe host. Exercise both explicit and implied timers, cache-token exhaustion as well as run-count limits, and the existing broken/lost-probe repair path. A reservation subtracts generic wakes; it must not create spend allowance. Worker copies inherit events but not home default budgets; a partial override still uses node-local defaults, so only reserve where limits are authoritative. Confirm remote-loss recovery actually supports the park shape before reserving its fallback timer; implicit remote parks may lack that repair. Verify the sweep's returned next-due timestamp, not only unchanged status, so a reserved expired timer does not force every-tick full scans.
- Treat impossible-producer wakes separately from generic timers when reserving a terminal run. `ci_run_unstartable` means the CI producer cannot fire (conflicted PR or unavailable runners), so suppressing its repair wake can leave only a stale timeout. Exercise real CI sweeps with one remaining authorized run, both spent-history and short-run accounting, and assert the remedy comment plus unchanged cap/spend.
- For explicit orphan adoption, test the real scope-authority reader after adoption and after chat-link reconciliation: a notification subscription can return successful decision ownership while synced renewal still requires an unreleased created link. Keep explicit authenticated adoption distinct from passive observer membership, and preserve released-owner/foreign/worker refusal. For cross-replica mandates use portable comment UIDs, retain same-writer/gateway and current-stop validation, and test remapped numeric IDs. When a Mac cannot show a hub card, inspect both its primary board and same-board sync-shadow before claiming the card is missing; exact-card read-only lookup and list/dispatch eligibility are separate contracts.
- For hold-notice repairs, exercise old already-published notices and a restriction added after an ordinary spend stop. The pending episode reader can intentionally return the original stop while later evidence tightens scope/safety; publication must carry effective restrictions, not just the original payload. Test a child's own hold and held parents together rather than allowing a single envelope choice to hide one signal. Malformed controls need nested non-scalar identities and scalar provider lists as well as invalid JSON/null/list roots; valid JSON alone does not guarantee safe hashing or iteration.

- Keep a stable hold episode separate from its current guidance revision: later scope/safety fences and authority corrections can leave the original spend event pending. Derive guidance from actual current restrictions, deliver changed guidance under a stable revision key, and test already-delivered ordinary advice followed by scope/safety tightening. A complete old notice must not suppress binding a missing authentic recipient; replay its existing event only for the new subscription. Missing authority never implies permission to run renewal commands.
- Compare hold audiences with creation's foreign-session provenance exception as well as the renewal reader. A foreign Desktop `local-<hash>` can look machine-only locally while its unreleased, fully qualified created link is accepted authority; a blanket machine filter can omit a legitimate owner. Preserve missing-profile/released/observer rejection rather than manufacturing provenance.
- For overdue scheduled cards, distinguish an `awaiting` CI label from an actual `wake_check`: the label alone does not subscribe to CI completion. Read canonical park/wake events and board-wide wake batches, then inspect retained per-process loop-accounting timings before blaming the timer predicate. An isolated deadline test that passes is a control, not a reproduction of a dispatcher tick stalled for minutes.
- For mutual waits, inspect structured producer records before reading opaque probe scripts. Gateway-qualified card edges can be skipped by a local cycle walker while its probe fallback also drops the same producer ref; later replica arrivals require current-graph reconciliation, not only admission checks. Do not treat arbitrary IDs in script files or prose as proven blocking dependencies, and never read a local path as evidence of a remote probe's code. Preserve board/gateway qualification, portable park identities, independent owner-notice identities and withdrawal after either leg changes; a cycle notice grants no release or spend authority.
- Follow every creation-provenance field when checking released inherited authority: decomposition can record a different source field from ordinary child creation. Test refusal/rollback against the actual renewal reader.
- Compose new notice kinds with existing blocked notices through real full/keyed/sweep delivery and ledger dedup; isolated envelope tests miss displacement. Exercise messaging formatters and queued fold/claim refresh as well as TUI delivery, including changed graph premises without a card-status change and conservative stale-replica controls.
- Trace concurrent signals through every projection, not only the publisher: a child can need its own decision and report a held prerequisite simultaneously. Preserve independent kind/event identities through full/keyed discovery, observations, published-index primary keys, claims and ACKs. Test both arrival orders and reset/dedup; changing only the envelope can leave the published SQLite index silently collapsing two signals.


- For reporting-only endpoints, test non-interference through the outer authentication layer, not only the handler's storage. Active-key lookup may renew registry contact and silently change stale-owner recovery eligibility. Snapshot registry freshness and recovery predicates for successful reads/writes, invalid requests, revoked credentials, and a normal-route refresh control.

- For spend-authority coaching, test both declarations and legitimate requests across reply and direct/deferred tool hooks. Keep currency totals separate from GPU counts (a model name such as "4090 GPU" is not thousands of GPUs); historical spend, denial questions and task briefs are not new authorization. Recover user-only scope rather than trusting an assistant's quoted approval. Test that the flow the hold note prescribes releases it: an explicit priced ask answered with a bare "approved" must exempt that figure (the yes carries no number), or the guard only logs false faults after a correct approval. Runtime notices that quote an ask are not the user's dollars. Prove the hold through a fresh throwaway chat as well as registered-hook discovery on each deployed host; a passing classifier alone does not prove the reply gate runs.
- For post-turn credential-scope errors, trace home and secret tokens separately: a retained home override is not credential authority, and copying an already-reset context cannot recover it. Bind the owning session's existing runtime scope at the lifecycle callback, without widening global credential allowlists or caching secrets in plugins. Test a real credential read on the copied worker context after secret teardown, distinct launch/foreign homes and tokens, and restoration of the remaining outer home on both success and judge failure.
- For native dependency scope errors after a passing pytest summary, inspect `patch.dict(sys.modules, ...)`: it rolls back the entire module map and removes unrelated lazy imports while native/runtime objects retain old module references. Substitute only the intended key and restore only that key. Compare a cold subprocess with a pre-imported dependency control, and assert post-exit stderr/stdout in a regression; pre-importing or filtering warnings alone masks the lifetime bug.
- For isolated plugin-suite dependency failures, provision the SDK version declared by core rather than the latest major: a newly installed major may change HTTP client types and invalidate real-wire fixtures. Verify cold subprocesses retain the parent test dependency paths while keeping isolated HOME and no-lazy-install guards. For AST-extracted core functions, keep their real lazy-import dependencies available through request execution, not only fixture construction; retain the original auth assertions.
- For intermittent plugin tests whose hook returns `None`, inspect swallowed-exception telemetry and fake-call counts before blaming timing. A background discovery of another checkout can replace a name-only `sys.modules` cache entry; the next mtime reload then discards the test's patched collaborator and calls real auth/model code. Record both module paths and reproduce by interleaving two checkout loaders at the hook boundary. Scope caches to canonical source identity, test equal mtimes and symlink aliases as well as reloads, and retain a mutation that breaks the original behavior assertion.
