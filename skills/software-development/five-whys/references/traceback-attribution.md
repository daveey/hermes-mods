# Traceback attribution

Reference for skill `five-whys`: its SKILL.md links this file from the step that needs it.

## Pitfalls

- Inspect the raising source site before treating an OperationalError as a SQL-query failure. SQLite wrappers can synthesize that class for Python tracking-registry or reader-lifecycle mutex admission before any statement runs. Keep these separate from native database busy/locked codes, missing schemas and unrelated UDF-registration failures. A source-site match attributes the observed occurrence only; it does not retroactively explain older class-only counters. Reconcile warning counts against accounting deltas after reload, and preserve unexplained omissions rather than treating logger silence as recovery.

- Class-only SQLite error counters cannot identify historical SQL, locking or missing-schema causes. Preserve that attribution gap even after the fallback fix yields a zero-error window. For the next natural failure, add reviewed, tested diagnostics that retain the SQLite error name and traceback basename/line/function sites while propagating the original exception unchanged; exclude raw exception messages, SQL, parameters, full paths and source lines. Assert diagnostic privacy with a real SQLite exception containing a private marker, and independently retain exception identity and fail-closed behavior. A new diagnostic is not proof of the historical cause. Match the diagnostic try boundary to the accounting scope: include context-manager entry and cleanup, and fault-inject both in addition to the query body. A body-only warning can remain silent while the enclosing pass correctly records an error. For designed no-adoption fallbacks, log only class and bounded source sites rather than the exception reason, which can contain a private path.

- For terminal traceback alerts, check the decoded exit status before attributing stdout to the tool. Successful log/source reads can contain real Hermes frames; prefixed log excerpts and truncated pytest output may lack a standalone exception identity. Never group these under a generic `terminal: traceback` fallback. Preserve explicit error metadata and pipeline-failure hints, and test both successful diagnostic reads and failed core commands through the observer. A classifier fix does not establish that every historical exception printed in those logs was repaired.

- For execute_code traceback alerts, recover the complete decoded tool envelope and originating cell before grouping incidents. Bundled Python lives under `.hermes/tools/python-*/lib`, so a generic `/tools/` frame match misattributes stdlib failures to Hermes; executor frames above `<cell>` likewise do not prove a core defect. Test raw, dict, JSON and guidance-suffixed envelopes, qualified exception tails, genuine core calls below the cell boundary, and successful cells quoting historical tracebacks. Replay stored results into an isolated sink, not the live defect ledger.
