# Clock fixture pitfalls

Reference for skill `five-whys`: its SKILL.md links this file from the step that needs it.

## Pitfalls

- Before an immutable time-bound live census, wait against the absolute not-before epoch and sample the wall clock again immediately before invocation. A guessed relative sleep can finish before the phase opens and consume the single durable attempt even though the inner gate correctly refuses; an early refused receipt is not permission to overwrite or retry. Preserve the actual invocation and remote snapshot timestamps, distinguish zero check attempts from a gateway timeout, and honor the existing final-slot disposition rather than inventing another date.

- For near-expiry CPU advisory tests, finish real task/board setup before stamping the sample. A sample only100ms inside the prelease limit can expire during setup and refuse before the modeled slow lease runs. Reproduce with a bounded setup-delay injection and capture the actual prelease reason/age; then bind only the CPU reader's clock to the captured boundary and explicitly advance the lease phase. Preserve real claim, lease-reached, unchanged-sample, stale-refusal and no-new-measurement assertions; never widen production freshness or call an unreached lease hook proof of final-gate failure.

- For reset-date display failures, trace the formatter's same-UTC-day versus cross-day contract before changing production. A fixed future epoch eventually becomes today (then expires), so a full-date assertion can fail without a display regression. Keep the full date/provider assertion and establish a non-today precondition with a module-local clock seam; use a still-active relative hold when admission checks also read real time. Search main for an already-landed fixture correction before duplicating it, and prove both live and replica consumers RED with the old fixture and GREEN with the correction. Keep old-head CI red and safety-held review gates distinct from the independently verified correction.

- For replay-after-receipt-expiry tests, preserve the original first-send identity, HLC and payload across the retry. A fixture deliberately generating a fresh HLC models a different, pre-fix protocol; retain it as historical evidence rather than forcing it green with unrelated age suppression. If reclamation scans an insertion-ordered prefix, age that prefix through the target receipt and assert actual receipt removal before replaying.
- When server lifecycle writes gain field clocks, compose a genuinely fresh post-transition client operation only after exercising the real transition (for example lease expiry through alarm). Preserve a separate pre-transition frozen-envelope control that must lose. Do not move every client clock far into the future: that can conceal the server-clock ordering defect the test was meant to expose. Separate multi-scenario integration loops into independently reported cases when the loop exceeds a per-case deadline; retain every assertion and the original timeout.

- When a fake monotonic clock still permits a persisted lease to expire under load, trace wall/monotonic reconciliation before increasing the fixture budget. An armed incident can resume using real `time.time()` even while `_mono()` is frozen. Bind both clocks locally to the same explicit advancement for that idle-path fixture; keep backend and reservation timing real. Check deadline-thread waits separately: `Event.wait()` does not advance a fake clock, while a patched `time.sleep()` may. Preserve phase-reached, no-launch, and release assertions and verify with starvation plus a disabled deadline-check mutant.

- For PR respawn-guard flakes after reassignment, distinguish review-checkpoint authorization from an independent operator handoff. A real `assigned` event strictly later than PR publication intentionally releases the hold, while a same-second tie stays guarded. Pin fixture chronology and test both 0/1-second offsets; assert `resumes_review` rejects the old owner in both, with a positive pre-assignment control. Do not change production ordering or widen retries to enforce an accidentally same-second fixture.
- For receipt-expiry fixture flakes, freeze the tested module's clock before recording scope/publication timestamps, not only at the final expiry assertion. Replace the module's time reference rather than global time.monotonic so test-runner deadlines remain real. Keep real lock/process/file checks and explicitly advance to the inclusive TTL boundary and just beyond it. Prove RED/GREEN with an external controller holding the test process in SIGSTOP past the TTL after publication, then SIGCONT; raising the production TTL or adding retries hides the fixture defect.
