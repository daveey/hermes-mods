# Concurrency test pitfalls

Reference for skill `five-whys`: its SKILL.md links this file from the step that needs it.

## Pitfalls

- For functional adapter conformance whose receive budgets include durable setup, inject a stall beyond the unchanged case budget at the real configured/dispatch boundary before attributing the historical timeout. Separate logical protocol/media time from a bounded runner watchdog; advance scheduled callbacks chronologically and preserve real-time safety tests separately. A byte watermark on a private clock channel certifies only delivered bytes, not stdout liveness: an already-satisfied count can beat pending EOF in the background drain. Exercise a real child closing stdout before its silence ACK while keeping the clock socket alive, retain a bounded wire silence/EOF probe with logical time frozen, and prove the negative RED/GREEN. A disconnect exception caught outside a multi-scenario accept loop can leave bound but unserviced sockets; regress the next scenario's actual negotiation, not just cleanup or the caught exception.

- For transport-independence tests, separate logical liveness age from CPU throughput: a free-running loop that resets its due time when late cannot guarantee a fixed tick count in a short real-time window under arbitrary host pauses. Prove the old observation fails with one bounded scheduling gap, then retain actual-tick and causal assertions using a finite run of the real production driver under its existing watchdog. Advance the injected domain clock and only the blocked send's liveness timestamps; replacing a shared Wire clock can perturb unrelated host heartbeats. Explicitly await entry into a blocked close before testing another boundary, and complete close before releasing the old sender so accelerated test production does not flush an artificial burst into the closing epoch. Mutation-test coupling the driver to the blocked socket. Keep original failed matrices, report changed-head results separately, and claim no wall-clock latency from logical-time proof.

- For paired bulk-download network controls, retain same-runner/same-IP/same-object simultaneous flows, complete-body hashes and TCP-header captures. A fast neighbour falsifies whole-runner bandwidth exhaustion, not a per-flow path defect. SACKs and RTT-scale sequence-hole recovery support loss/recovery but do not locate the faulty hop; zero local capture drops do not rule out upstream loss. GRO makes captured packet counts unsuitable as wire-loss denominators. Do not change receiver BBR to fix a remote sender's congestion control, infer an HTTP2-only cause when HTTP1 controls also degrade, or equate different clients/payloads/thresholds' failure rates.

- For cold-bootstrap stalls, capture the downstream package manager before blaming Python locks or pipes. A Python worker polling a live uv child and a bootstrap parent in `pipe_read` can be healthy waits while bulk downloads progress too slowly. Compare full-wheel transport throughput and per-socket byte counters, not just fast index/metadata probes or time to first byte. Keep successful-control logs too: truncating all green stderr can erase whether those controls downloaded or reused cache. Detect Python executables by the basename of argv[0], not a fixed prefix of a long managed-interpreter path; the latter silently omits the worker whose stack matters. A 120-second diagnostic threshold is not the same as a 300-second product timeout; report those counts separately.

- For state-machine health evidence, trace the field through successful commit, failed-action observation allowlists, multi-slot quiet updates, and dry-run shadow load/save. A decision-only regression can pass while a sibling write failure discards an unhealthy reset and the next real tick acts on pre-interruption evidence. Exercise real ticks against the ledger with fake transports. Distinguish invalidation (must survive failure) from evidence consumption tied to an uncommitted lifecycle transition (must not survive failure or preview), covering legacy and multi-slot paths.

- For async optimistic-update tests, a short pre-action sleep and a longer fake-transport delay do not establish completion order under actor scheduling. Gate transport entry/release with one-shot event latches, await each task completion, preserve the original order-dependent assertion, and cover the reverse order's state-preservation invariant separately. A sleep-free RED that forces the opposite order while retaining the original assertion proves the source mechanism; it does not reconstruct a historical schedule. Label delay-based RED as corroboration only, and disclose whether latch waits have only an enclosing CI timeout.

- For seeded state-machine harnesses with fake logical time, a short real deadline around a healthy fake observation is an unseeded fault source: host starvation can consume required coverage paths or convergence evaluations. Keep healthy observation deadlines beyond the enclosing test watchdog, retain explicitly scripted timeout faults and every coverage/convergence assertion, and regress each setup/reset/restart path with a delayed-but-successful fake. Record actual before/after rates under identical CPU affinity, contention and runtime concurrency. If the top-level harness enforces complete-shard accounting, replay individual seeds through the existing seed runner in a dedicated test rather than weakening the full-shard guard to admit filtered partial coverage.

- For synthetic recurring occurrences, do not allocate identities with `floor(now) - counter`: a one-second scheduling gap cancels a one-step counter increment and reuses a completed slot. Anchor offsets to an immutable per-job timestamp, keep slots inside grace, and exercise exact 0/1/2-second clock advances through the real dedup path. A completed-occurrence warning plus a missing downstream failure stamp can be correct scheduler dedup acting on a broken fixture, not a timeout defect.

- For self-SIGSTOP scheduling probes, prove failure-path cleanup before relying on normal-path RED/GREEN. A timeout before the controller captures the stopper PID can kill the outer wrapper, trigger a supervisor parent-death handler, and enter a new stop after cleanup has finished. Disarm future checkpoint entry and acknowledge/resume already-entered stops with a race-free protocol; a sentinel alone does not cover the write-to-SIGSTOP gap. Exercise missing-PID and concurrent-entry timeout paths with real subprocesses rather than relying on CI runner orphan cleanup.

- For native-process ownership tests, `Popen` returning does not guarantee that psutil can already observe nonempty argv: the close-on-exec handshake can precede argv publication. Synchronize on the raw argv precondition, not by retrying the ownership verdict (which could mask a parser defect). For a bounded Linux scheduling-gap reproduction, have a controller inspect only the test parent's newborn children, SIGSTOP those with empty `/proc/<pid>/cmdline`, then SIGCONT after a short hold; always resume stopped children in `finally`. An untargeted duty cycle may miss this narrow window, so record baseline failures and fixed passes separately.

- For psutil descendant-liveness polls and teardown, enumeration does not keep a child alive until `cmdline()`, `terminate()` or `kill()`. Catch `NoSuchProcess` per child (it includes `ZombieProcess`), continue scanning/signalling live siblings, and leave other errors visible. Teardown must also tolerate disappearance between `Popen.poll()` and psutil lookup. In a lookup-boundary regression that kills/reaps a real child, restore the original psutil constructor before signalling: the live-system signal guard itself queries psutil and otherwise recursively re-enters the injected lookup. Prove both exit-before-reap and reap-before-read with real children killed at the argv-read boundary plus a live sibling control; do not widen deadlines for an observation race.
- For socket bind flakes, locate which listener failed before assuming a timeout: failure of the first listener after a bind/close free-port probe is an allocation TOCTOU. Bind the real first listener to port 0, read its allocated address while it still owns the socket, then use that exact port for conflict/rebind assertions. Reproduce with a real competing listener at the probe-return boundary plus targeted SIGSTOP/SIGCONT; preserve intentional conflict assertions and finally-cleanup even on first-connect failure. The intentional disconnect-to-rebind gap remains distinct from the avoidable initial probe gap.
- For procfs liveness-test failures, distinguish a missed deadline from successful process disappearance: catch only `FileNotFoundError` (ENOENT) and `ProcessLookupError` (ESRCH) at the stat-read boundary. Linux can open `/proc/<pid>/stat` successfully, then return ESRCH from the already-open file's `read()` after reap. Prove this using an owned real child held on stdin: open its stat file, close stdin and wait for normal exit/reap, then read that same stream. Retain live-child, already-reaped and unrelated-error controls; this is observer handling, never permission to swallow an escaping product reap error. Reproduce deterministically by intercepting the target stat read, killing and waiting for a real child, then performing the original read; retain a live-child control. Broad SIGSTOP/SIGCONT duty cycling can validate load tolerance but does not reliably hit this narrow race. A liveness predicate must also count `X` (EXIT_DEAD) as exited, not only `Z`: while the reaper is inside wait(), /proc shows Z, then X, then nothing. A fast fail (well under the poll deadline) points to a re-read after the loop already saw the process die. Assert on the loop's own last observation and pin the process's starttime (stat field 22) to detect pid reuse. To show RED, reap real children while a separate poller process reads /proc.

- For stat-only cache fingerprints, distinguish semantic inputs from generated metadata: creating an ignored `__pycache__` still moves its parent's mtime. Reproduce at the exact record-write/read boundary by creating the ignored directory and explicitly moving the parent mtime, while retaining real plugin/config invalidation checks. Check a reported CI run's head ancestry before treating a newly delivered flake notice as a post-fix recurrence. A starvation controller must pause all descendants, not only the runner's process group: per-file runners may create new sessions.
- For a pass loop that exits on "no worker still running" (thread-pool vets feeding a train), order the completion check before the data read it acts on: a worker that stores between `read queue` and `f.done()` is done yet absent from the read, so the loop exits with the item unprocessed. Always re-read after the done() checks, record which futures that read covers, and rerun for any finished later. Reproduce deterministically by gating the worker on an Event released from the exact seam (a proxy for the pending map's `items()`, or the idle-phase hook); SIGSTOP duty cycles on the whole process do not change intra-process interleaving and will not hit it.
- For `int('')` from a pid file, the reader waited for the file to exist: `write_text` creates before writing. Wait for parseable content (or have the writer `os.replace` a tmp file); prove RED by injecting a sleep between the probe's open and write.
- For multi-line CLI output flakes, synchronize on the field being asserted, not an earlier line: a command can print an ID before a store/RPC read and then print its title. Reproduce partial-pane observations at the capture boundary while retaining real CLI/data assertions; prove the old wait fails and the corrected wait passes. Run targeted SIGSTOP/SIGCONT coverage too, discovering detached tmux CLI children by exact argv and task-specific environment rather than assuming the runner process group contains them.
- For PTY idle-read flakes returning only CRLF, inspect the output-consumption predicate before raising wait bounds: payload visibility does not consume its line terminator. Force real reads to one byte at the target fd, consume the full expected frame, and retain the original idle-wait assertion. Keep test children blocked on input until teardown instead of expiring on a wall-clock sleep. A Linux starvation controller must enumerate every `/proc/<pid>/task/*/children` entry: subprocesses spawned by runner threads may be absent from the leader thread's children list; record nonzero stop cycles so an unexercised stress run cannot pass as proof.
