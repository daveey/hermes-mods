# B3-only source activation and rollback receipts

**UNACTIVATED.** This is a downstream interface and evidence checklist, not
permission to compose a production owner. Source merge, installed checkout SHA,
manual composition, a cached model, a callback and native pixels are different
facts. B3 owns activation only after its original prerequisites are accepted.
PanelModel remains v1; no Desktop classifier or new default runtime caller is
introduced by this source milestone.

## Existing API and ownership

- `Feed.compose_board_sources(reader_factory, gateway=..., profile=...)` explicitly
  opts a Feed into the reserved owner. Manual composition is inert until driven.
- `Feed.ensure_snapshot_service(api_generation, reader_factory)` completes an
  existing opt-in; it cannot opt an ordinary Feed in. Saved predecessor RESTART
  entries can establish that owner before or after current API registration.
- Current canonical readers and source readers are current-generation capabilities.
  A predecessor's already-imported reader is never an authority fallback. Compatible
  stopped-store transfer preserves immutable versions/admissions/retry ages, not
  connection ownership. Disk restore carries presentation, never source coverage.
- One local acquisition, one strict external acquisition and two pure projections
  are the complete worker-role budget. A completion marker does not release a role:
  actual thread exit and predecessor retirement still fence replacements.
- Keep B1 acquisition/store and B2a `project_board`, `project_boards`,
  `carry_board_observations`, `publish_projections` contracts. Demand/watch/lineage
  and the exact accepted source vector fence publication; canonical current consent,
  decisions and execution remain independent. Missing coverage is unknown.

## Before an authorized measurement window

Record actual serving route and process birth, installed and *loaded* mods/core/API
identities, current reader factory, Feed epoch, source-store owner epoch, current
and retiring role thread identities and any service thread. Record target
connection/profile/session plus exact demand, watch token, lineage and accepted
source vectors. Identify the last accepted uncomposed release/reader/API artifact
as the rollback target **before** making an activation change. This document does
not choose or install that artifact for B3.

Install the private `ReceiptLog` with `Feed.install_receipts(log)` before the
measured source admissions. That operation records evidence; it does not activate
sources. Keep raw payloads, source scopes and expected row/action/absence manifests
private. Retain exact log/runtime/window IDs and hashes. Do not replace real payloads
with smaller measurement objects, lower the real push ceiling or fabricate missing
counters as zero. `rows_returned` is physical fetched rows, `selected_logical_rows`
is a separate logical count; VM work is measured in 100-instruction quanta.
Unavailable external row/VM costs and unavailable profiling are unavailable.

## Inclusion and successor windows

`changes_packet()` carries immutable payload bytes plus publication sidecars. A
successful exact post-transform `_emit` is server emission only. An invalidation
is not model inclusion; a scoped catch-up qualifies only with core-owned
hosted/loopback admission, exact scoped publication custody and successful final
ASGI body writes. Failed emit/write, no catch-up and a superseded older publication
remain unmatched with their original admission age. `no_change` alone never
acknowledges acquisition, execution or authenticated inclusion.

On natural reload, keep the predecessor logger/window and identity separate from
the successor. Current code does not transfer receipt-log identity via `resume`.
Bind a fresh successor logger explicitly, preserving predecessor raw records and
any unmatched/superseded admission linkage. A source-store transfer is not a logger
transfer and does not excuse a gap between windows. Preserve interrupted cohorts as
NO_PROOF instead of treating missing samples as latency passes.

## Producer drain and window close

Stop new measured admissions through the authorized lifecycle. Set the Feed stop
signal and close its source owner; verify every acquisition/projection thread,
service thread and retiring ancestor actually exited. The bounded `close()` return
alone is not a claim that blocked I/O drained. Keep its logger open until those
producers have stopped recording. Then `flush()` and `close()` the log, preserve the
terminal `window_end`, and run `validate_records(..., require_closed=True)` plus
the stage analyzer on the actual raw bytes. Require no loss/write errors and no
unexplained unmatched admissions. Failure, right-censoring and unavailable costs
remain in the denominator/report. Do not close a logger while a late producer can
still write and then report a clean terminal accounting record.

## Rollback procedure

Before activation, leave composition uncalled. After an approved activation:

1. Use the authorized serving lifecycle to stop the composed Feed and withdraw its
   store authority. Do not kill busy Desktop sessions or delete a live owner field.
2. Verify actual role and retirement drain as above, retain interrupted/unmatched
   evidence and close that generation's measurement window.
3. Construct a clean **uncomposed** Feed using the recorded accepted rollback
   reader/API artifact. Do not `resume()` the source-bearing Feed to roll back:
   resume intentionally carries its explicit opt-in. Do not revive a retired store.
4. Verify a distinct clean Feed/store-authority state, current canonical request and
   execution ownership, warmed scoped response and unchanged default routes. Record
   process/route/birth and loaded artifact readbacks; a checkout reset is not proof.

## Gates this receipt cannot waive

B3 still owns simultaneous installed-runtime/model/native proof, original semantic
and negative-consent cases, all-route/population/FIFO/retry/role acceptance, real
serialized-writer contention, full/decision/observation/heartbeat timing, CPU and
end-to-end inclusion latency. Synthetic fixtures and server TestClient writes are
not native or live transport proof. The original failed 50 ms projection maxima
remain failures; acquisition success and a source-only merge do not complete B/C,
performance or native acceptance.
