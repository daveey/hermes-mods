# Denial-substitution guard — unpublished M1 containment

This is a policy mistake guard, not an authorization sandbox. Full-goal acceptance is incomplete. Do not enable or publish this candidate before independent exact-head review and the remaining acceptance work.

## Rule
An observed denial of action/resource stays held on recognized repeat invocations. Same identity, different identity, elapsed time, switching client, owner-terminal reason text, or a writable JSON file never establishes subsequent authority. There is no TTL and no grant-import protocol. `verify_receipt` returns UNAVAILABLE. No independently protected exact-denial authority producer is integrated; the genuine-authorized route remains unproven. No reset or override API is offered.

## Observation and state
Known terminal/execute-code/tailnet output envelopes are decoded before parsing; multiple denial lines retain local qualifiers and evidence hashes. Text is conservative observation, not authenticated AWS evidence. Missing action/resource uses UNKNOWN. Exact recorded executable-text fingerprints hold before invocation parsing, including opaque scripts and unmapped CLI operations; with both action and resource UNKNOWN this is the only correlation. Deduplication always includes the fingerprint alongside action/resource/principal/explicit/execution host, so different denied invocations do not erase each other's replay evidence. Repeated identical observations still deduplicate; distinct fingerprints consume the existing bounded row/byte capacity. File-path-only extraction is not an executable fingerprint.

Result decoding visits every string leaf of the post-hook result (all dict values except an echoed input `command`, lists, JSON-in-string, the registry's multimodal `{_multimodal, content}` dict), up to nesting depth 12; deeper structure is serialized and scanned as raw text (including any `command` it contains). Yielded leaf text is charged in characters (not UTF-8 bytes) against the 8Mi ledger bound, and any single string over it is refused. When a result cannot be fully observed (bound or nesting failure), the rows parsed so far are kept and an UNKNOWN/UNKNOWN `observation: incomplete:*` row holds exact replay of that invocation (a possible false hold for huge non-denied AWS output); this does not latch the ledger unhealthy. The total-character bound is per result: a direct (non-JSON-string) dict result whose leaves together exceed it keeps exact-replay protection but loses semantic rows parsed after the bound; stock handlers return JSON strings capped far below it. Envelope shapes follow `review-envelopes/RESULT-SHAPES.md`, a static read of the installed core: `process_manage`/`process` poll/log/wait results are recorded under the terminal command the result echoes (`output_preview` included), tailnet `stderr`/`detail` and nested `error.message` are read. Text omitted by a handler before the hook (terminal head/tail cap, process poll 1,000-char preview, tailnet 8,000-char cap, registry 2,048-char `error` clip, user-terminal 12,000-char tail) is not recovered; spill files are not followed. Sequential `execute_code` inner calls may not emit their own post hook; then only what the code printed is observed.

Besides IAM `not authorized to perform` text, a line `An error occurred (CODE) when calling the OP operation` is a denial when CODE is AccessDenied[Exception], UnauthorizedOperation, Unauthorized[Access|Exception], AuthorizationError[Exception], Forbidden[Exception], NotAuthorized[Exception] or 403 (throttling, expired/invalid credentials and validation codes are not). Such a row has resource UNKNOWN, principal UNKNOWN and action `<service>:OP` with `action_kind: "api"`. The service comes from each recognized call whose own operation is OP or whose listed IAM candidates include OP (that candidate's service, e.g. `cloudformation deploy` failing PutObject gives `s3:PutObject`; several give one row each); failing that, the single recognized service; else UNKNOWN/UNKNOWN (exact-fingerprint replay only). Text is not authenticated: a non-reader command that merely prints quoted AWS errors can record rows (exact-replay false holds; semantic false holds when a service is recognized). An API row matches any call sharing one of OP's IAM candidate actions. A line already parsed as IAM text is not also parsed as an API error. Row `v` must be the integer 0 or 1 (bool/float rejected); `action_kind` must be absent or `api`.

Exact replay is deliberately transport-neutral: tool name and destination host are not fingerprint inputs, so identical shell text observed on one transport can hold on another. This is conservative local correlation, not shared cross-host history or proof of resource equivalence. Legacy rows without fingerprints cannot hold opaque replay. Unhealthy states (persistent cap marker, in-process latch, invalid line, byte or row cap) still return every valid durable row readable within the byte bound (a row whose validation raises outside ValueError/TypeError/UnicodeError, e.g. OverflowError on an out-of-range number, still fails the whole read as before, which holds recognized mutations through the classifier-failure path), so they hold everything a healthy ledger would, and additionally hold every recognized AWS mutation; this process's bounded overflow sample (128 rows, not durable) of denials observed after the cap also applies. Denials first observed after the cap in another process, or beyond that sample, are not held for reads or opaque scripts. Changed script text, partial batches, and plausible-AWS observation filtering remain coverage limits; no arbitrary-code containment is claimed.

Semantic matching maps a recognized CLI/SDK call to IAM `(prefix, action)` candidates before comparing with a recorded action. Service prefixes come from a table of known CLI/boto3 names that differ from their IAM prefix (`s3api`/`s3control`→`s3`, `stepfunctions`→`states`, `elbv2`/`elb`→`elasticloadbalancing`, `sesv2`→`ses`, `opensearch`→`es`, `emr`→`elasticmapreduce`, `deploy`→`codedeploy`, `apigatewayv2`→`apigateway`, …), plus the name itself and the name with a trailing `vN` removed. Operations keep their own name and add table entries where the IAM action differs: the closed set of high-level `aws s3` commands (`cp` = Put/Get/ListBucket, `mv`/`sync` add DeleteObject, `rm`, `mb`, `rb`, `ls`, `presign`, `website`), boto3 managed transfers (`upload_file*`, `download_file*`, `copy`), s3api operations such as `head-object`→GetObject, `list-objects-v2`→ListBucket, `delete-objects`→DeleteObject, multipart parts→PutObject, `*-bucket-lifecycle*`/replication/encryption/public-access-block configuration actions, `lambda invoke`→InvokeFunction, `emr create-cluster`→RunJobFlow, and a few CLI customizations (`ecr get-login-password`, `eks update-kubeconfig`, `cloudformation deploy|package`, `deploy push`, `codeartifact login`). Candidates are a union, so a direction-ambiguous command (`s3 cp` upload vs download) can hold conservatively after either denial. A recorded IAM action containing `*`/`?` is matched as a case-insensitive glob. Not contained: unlisted operations whose IAM action name differs from the API name, actions one call needs on another service beyond the listed customizations, and services missing from the prefix table whose IAM prefix differs; for these only exact replay holds.

The AWS CLI accepts global options anywhere (argparse intersperses optionals; option table from the installed AWS CLI v2 `awscli/data/cli.json`). Service and operation are the first two non-option words after `aws`, skipping global options before and between them: value options (`--profile --region --endpoint-url --output --query --cli-read-timeout --cli-connect-timeout --ca-bundle --color --cli-binary-format --cli-error-format`) consume one word, flags do not, `--opt=value` is one word. An ambiguous spelling (prefix abbreviation matching options of both arities, a bare unknown `--x`, or a value option followed by an option-like word) yields both readings; an unknown single word (`-x`, `--unknown=v`) yields one reading marked uncertain. More than six branches is UNKNOWN (held as static analysis unavailable). Relative to the prior first-option-only parser, correct placement can also remove false holds where a global option was misread as the operation; extra readings otherwise only add candidate service/operation calls. Resource selectors are read only from words after the operation, and only for a reading in which every earlier word was a recognized global option or its value with a single reading; any unknown, ambiguous or `--`-separated pre-operation word makes that call's resource scope unknown (no instance adapter ALLOW). Option scanning is linear in argv length, and one classify call extracts each text's invocations once for all ledger rows, matching resources only after the action matches.

Production captures `account_default_hermes_home()` at registration, sharing one ledger across this OS account's profiles on this host. It ignores later HERMES_HOME/HOME/cwd changes. Core platform suffix/default behavior remains relevant across process startup; cross-user/host history is not shared. Tests inject explicit synthetic roots, not a production env override. Legacy per-profile inventory/migration remains incomplete.

JSONL rows retain action, resource, principal, qualifier, timestamp, invocation hint and correlation/evidence hashes. `at` is a validated timestamp alias for compatibility; it must agree with observed_at. Valid v0 rows are read without expiry. Invalid/malformed/unreadable state causes a narrow hold on recognized AWS mutations, preserving explicitly known reads and non-AWS calls.

Dedicated advisory flock guards read/append. Reads create the root and lock file; lock acquisition has no local timeout. Append validates, deduplicates, writes O_APPEND and fsyncs before return, including the root directory on first ledger creation. This is not a crash-durability proof. No lock spans command dispatch. Cap defaults: 8MiB/20000 rows; ledger rows are not dropped or expired. Overflow writes a persistent cap marker; marker presence is unhealthy even with later higher cap constants. Only the latest 128 overflow observations per root are retained as diagnostic samples; these samples are not authorization state. Write failure is latched in-process and logged, not claimed durably safe. Complete crash/failure characterization remains required.

Legacy rows with both action and resource UNKNOWN and no invocation fingerprint make the ledger unhealthy, rather than silently losing the denial. This holds recognized AWS mutations, while known positive reads and non-AWS calls remain allowed. No repair/reset or grant path is provided; legacy inventory and operator disposition remain an open deployment prerequisite.

## Tested entry paths
`tests_guard.py` uses synthetic explicit roots and covers terminal CLI, literal execute_code terminal and boto3 forms, direct tool_call envelope classification, tailnet classification, user-terminal reason rejection, unrelated-action/resource controls, and callback recording/block responses. These are offline fixtures, never cloud probes. Native local multi-entry tool_call is rejected by current core; direct classifier envelopes are not proof that native batch execution exists.

External gates kept outside this repo (review evidence): an immutable 49-probe adversarial corpus, 26 native core-dispatch controls, the actual account-root resolver contract, and UNKNOWN-fingerprint/fresh-process cap regressions. Those gates report HOLD/GAP per probe; a GAP is a documented uncovered spelling, not a pass. The in-repo `tests_*.py` suites do not replace them.

## Known limits — still open
- Parser is a bounded shell/Python subset (details below): dynamic arguments, aliases, script files, some SDK forms, raw SigV4/HTTP and transformed resources are not contained.
- AWS invocation detection (`_shell_invocations`): assignments, reserved words (`if then else elif fi do done while until ! { } time in`) and `function NAME` are skipped at a command head; after a wrapper (env sudo doas command exec nohup nice ionice timeout stdbuf setsid time xargs flock unbuffer builtin chronic taskset chrt caffeinate watch strace ltrace runuser nsenter unshare chroot systemd-run script) the first later word that is `aws`/`token-broker`/`bash`/`sh`/`zsh`/`eval` is the wrapped command (wrapper option grammar is not modeled; an option value spelled `aws` is taken as the command, which can be a false ALLOW as well as a false hold: `env -u aws aws ec2 ...` is read as service `aws`, not contained). `eval` re-lexes its joined words. A dynamic command word (`$X`, `$(..)`, backticks) in text that mentions `aws` is UNKNOWN (held as static analysis unavailable). Python: subprocess/os/posix/nt/asyncio/asyncio.subprocess/pty process launchers pass literal strings, literal argv lists and literal variadic argv (`os.execl*`/`spawnl*`/`create_subprocess_exec`/`loop.subprocess_exec`; for exec*/spawn*/posix_spawn* the path/file argument is taken as the program and argv[0] as a label) to the shell detector. A method call is a launcher when its attribute is a launcher name other than the generic `run/call/spawn/popen`, whatever the receiver chain (so re-exports such as `subprocess.os.system` and event-loop `subprocess_exec/subprocess_shell` are covered; a same-named unrelated method is analyzed too, a precision cost only in code that spells aws); generic names need a launcher module somewhere in the receiver chain (`asyncio.subprocess.subprocess.run`). Bare-name calls and receiver aliases resolve through import bindings (`import M as A`, `from M import f as A`, and `from ANY import LAUNCHER_MODULE as A`, e.g. `from subprocess import os as o`), which are a scope-insensitive may-alias union (an import in any scope, including `from M import *`, adds a binding and never removes one; a function name imported from two different launchers is UNKNOWN when the code mentions aws); code mentioning `aws` that uses a relative import (`from .x import y`, package unknown) or dynamic module/attribute access (`__import__`, `importlib.import_module`, `sys.modules`, `getattr(`, `globals()/locals()/vars()`, `__builtins__`, `operator.attrgetter/methodcaller`) is UNKNOWN; a non-literal command/argv, a starred or `**kw` argument, a starred element inside an argv list/tuple, or an incomplete argv in code mentioning `aws`, or an `executable=` override (any launcher, including `create_subprocess_exec`) that is `aws` or non-literal, is UNKNOWN. Wrappers followed by a dynamic word (`env "$C" ...`) in text mentioning aws are UNKNOWN; `env -S/--split-string` re-lexes its string. Not contained: aliases, functions called through other names, PATH shims, wrappers not listed, launchers rebound by assignment (`run = subprocess.run`, `x = os`, `g = getattr`), launchers passed as values (`map(os.system, ...)`, `Thread(target=os.system)`), `os.__dict__[...]`, `pkgutil.resolve_name`, `from sys import modules`, `exec`/`eval` of code strings that launch processes, ctypes/libc and third-party launchers (`sh`, `pexpect`, `plumbum`), and argv built at runtime in code that never spells `aws`. Precision cost: aws-mentioning code that uses dynamic attribute access (e.g. boto3 scripts with `getattr(`) becomes UNKNOWN (still held) instead of a precise operation, so a read-only script of that shape is held.
- Resource matching currently uses short-id tokens, not complete account/region equivalence.
- Same-uid code can alter ledger, marker, plugin or hooks; tool-text tamper checks are best effort, not filesystem protection. Root-level spellings are also held: a mutator operand naming the ledger root (any `.hermes` directory, `$HERMES_HOME`, the configured/account root) or an ancestor (home, `~`, `/`), a glob in that directory matching a ledger file name, and a cwd glob after a static `cd`/`pushd`/`chdir` into such a directory or home/OLDPWD in the same text. Not modeled: the persisted terminal cwd from earlier calls, dynamic `cd "$VAR"` targets, symlinks/bind mounts to the root, and any write by a script file, binary or other process.
- Transports: `ssh`/`watch` (remaining words are shell text), `uv`/`uvx`/`pipx`/`poetry`/`pdm`/`conda`/`mamba`/`micromamba` launchers (next AWS/interpreter word), `python -m awscli` (as `aws`; `-W`/`-X` values skipped), `python -c CODE` (analyzed like execute_code); interpreter words after a wrapper are analyzed in addition to the first AWS-family word (first 4); in-process `awscli` driver imports/run_module and non-literal `hermes_tools` shell commands in AWS-mentioning code are UNKNOWN (held); a boto3 `.resource('svc')` counts as any action of that service (no resource scope). Remote execution through other tools (remote IDEs, CI jobs, scheduled tasks, containers' own shells) is not seen.
- Shell fed from data (`_fed_consumer`/`_fed_invocations`): when the text (or an enclosing text) contains a here-string `<<<`, process substitution `<(`/`>(`, a `.` command or any word named bash/sh/zsh/dash/ksh/mksh/ash/fish/busybox/eval/source, data words are also analyzed as code: each word containing whitespace and `aws`/`awscli`/`python`/`token-broker`, and the words after the first AWS/interpreter word of a non-AWS command (`echo aws ...`). This covers `bash <<< CMD`, `echo CMD | sh`, `printf CMD | bash -s`, `eval "$(echo CMD)"`, `bash <(echo CMD)`, `source <(...)`. It is token-presence based, not data-flow: it may hold text that only prints an AWS command when a shell word appears elsewhere in the same text (a false hold), and it does not follow text through files, variables, or programs other than the shells named (e.g. `perl -e`, `node -e`, `xargs sh` input via a file). Also not contained (review-cumulative-2/delta): a command held in a variable then fed (`c='aws …'; echo "$c" | bash`), a command split across separately quoted words, `python3` reading code from stdin, csh/tcsh/rbash/pwsh, GNU parallel, awk `system`, base64- or otherwise encoded text, and `bash < FILE`.
- Tool names: `mcp__`-prefixed spellings are treated as the bare tool; `tool_call` accepts the `calls` list and the legacy single `{name, arguments}` shape with dict or JSON-string arguments. Beyond 16 nested envelopes, or JSON arguments too deep to decode, the call is held unconditionally as static analysis unavailable (fail closed, a false hold for benign deep nesting). Core reverses wire names and unwraps `tool_call` before hooks; this is defence in depth.
- Shell tamper analysis limits (`_shell_baseline`): text the bounded shell analysis does not inspect gets the baseline rule, never "no mutation". Uninspected means the unparsed suffix after unsupported list syntax (a `case` command, an unsupported function form, a redirect after a `( )` group, leading operators, a missing separator, group/compound depth over 6) — a failure inside a compound body makes everything after it uninspected —, a lexer error (unclosed quote, trailing escape) or the 16384-token cap; the whole text after a stray top-level `)` (the prefix may be misparsed, e.g. a case pattern or a substitution closed early); and the whole text past the nesting (bash -c depth over 6) or 262144-character source bound (exhausted shared work: see the legacy floor paragraph, fail-closed). Rule: a shell write keyword plus a literal protected name, or plus a `$NAME`/`${NAME` reference to a name that held a protected or top value anywhere in the analyzed text (flow-insensitive). The inspected prefix keeps its precise verdict, so a read of a protected file before unsupported syntax stays allowed. Not contained: names built dynamically inside the uninspected region (fragment concatenation such as `A=denial-; B=grants.json` then `$A$B`, printf/glob/brace construction), write verbs outside the shell keyword set (setfacl, tar/unzip extraction, git checkout), exported-variable inheritance by grandchild shells, and the general Python-nesting-bound case where the protected name is never literal (baseline limit, same as Python). Precision cost: a protected name read in the prefix plus any write verb after a stray `)` holds; a `read`-set (top) variable written inside unsupported syntax holds.
- Shell compound commands: unquoted reserved words (`if then else elif fi while until do done for select { } ! time`) structure commands and are never taken as the command word. if/while/until/for/select/brace bodies, including their conditions, are analyzed with may-run join semantics (any body command may or may not have run); loops iterate to a fixpoint, after 4 passes still-changing values widen to top. `for`/`select` variables take a protected word value when any listed word is protected, or top when any word is uncertain or there is no `in` list. Redirections on a closer (`done > F`) are checked. Function definitions (`name() BODY`, `function name [()] BODY`, with the body on the same or a later line) run nothing; a call by the literal name runs the body inline with loop semantics, so its assignments reach the caller (recursion guarded); every body is also analyzed after the main flow seeded with every name that held a protected or top value (indirect calls, calls from substitutions). `eval` analyzes its joined arguments as shell code with the current variables. `$'..'` words are lexed with backslash-escaped quotes (escape sequences undecoded: such a word is uncertain). Command substitutions referencing a name that held a protected or top value are re-analyzed with that value (flow-insensitive). Not modeled: `case` (uninspected remainder rule), `local`/dynamic scoping (function variables are global), aliases, `trap` handlers, `coproc`, arithmetic `for ((..))` and `[[ ]]`/`(( ))` (plain commands or unsupported syntax), external `time`/nohup/nice/timeout wrappers.
- Shell mutator coverage: the precise analyzer checks rm/unlink/rmdir/cp/mv/tee/truncate/touch/install/sed -i/sudoedit/dd operands, and conservatively holds shred/chmod/chown/chgrp/ln/link (any protected operand, including link targets: `ln -s P alias` holds), rsync (destination; every operand with `--remove-source-files`) and find with a mutating action (-delete/-exec/-execdir/-ok/-okdir/-fprint*/-fls) when any word is protected or a -name/-path pattern matches a protected basename or names `denial` (`find . -name '*.json' -delete` holds). The baseline keyword set includes these verbs and `-delete`. Not contained: `find . -delete` with no name pattern, xargs-fed operands (`... | xargs rm`), other mutating tools (setfacl, mkfifo over, tar/unzip extraction, git checkout, editors).
- Shell legacy floor: the compound/function/case/`$'..'`/complex `${..}` parsing above is precise-only. When the precise pass allows (or hits an analysis limit) after parsing any such construct, the accepted pre-compound analysis (functions/case/stray `)` as unsupported remainder under the baseline rule, no `$'..'`/complex `${..}` lexing) reruns on the same budget list from the same start; either holding holds and the caller keeps the larger consumption. The precise pass can therefore only add holds relative to that floor; it also inherits the floor's precision costs (e.g. `cat P; case x in a) echo > out;; esac` holds). Each command charges its text plus one unit per tracked name, so many empty variables cannot make state copies unbounded. Because that charge exhausts the shared 1Mi budget earlier (about 1.2-1.5k tracked names), exhausted shell work (or analyzer recursion) is fail-closed: the whole text holds unconditionally (a write-keyword test missed unlink/rmdir/touch/sudoedit and split command names), at top level, inside `bash -c`/`eval` children, and for a Python call whose nested shell strings exhaust the shared shell budget (the whole Python code holds). Structural limits (unsupported syntax, depth, source size) keep the baseline rule above; Python's own 16Mi work bound and Python-side RecursionError keep the Python baseline rule (unchanged limit). Precision cost: texts whose analysis exhausts the budget (thousands of commands/tracked variables) hold even when read-only.
- Shell parameters: positional parameters (`$1`..`$9`, `${N}`, `$@`, `$*`) are bound at a literal-name function call and by `set [--] ARGS`: every position takes a protected argument's value when any argument is protected (top when any is uncertain or only glob/brace-protected), otherwise the literal per-index values; `shift [N]` shifts per-index values; the caller's positionals are restored after the call. Function bodies analyzed after the main flow (indirect calls) get positionals from a tracked protected value, else a protected name written literally in the text, else top when any tracked value is top. Declaration builtins (`export local declare typeset readonly`, options skipped) assign their NAME=value operands like plain assignments; `-n` namerefs make the name top with an explicit issue. Complex `${..}` expansions (operators, indirection, arrays) are never decoded: the word is uncertain when the inner text names a protected fragment (`denial`, `grants.json`, `ledger.jsonl|cap|lock`) or references a name holding one or top (`${!..}`: any tracked such value), else an opaque non-protected value; `${N:=x}` stores top when risky. Output of a `$(..)`/backtick substitution whose code names a protected fragment is an uncertain word; `eval` with an uncertain word holds when the command references such a value. An unquoted brace expansion in a word containing `denial` is protected. Not contained: fragments not containing these markers (`den{ial,x}-grants.json`), substitution output computed without naming a fragment (`$(ls)`), `${N:=x}` strong stores.
- Python tamper analysis (`_python_analysis`) recognizes AST mutation sites (open/io.open/os.open modes and flags, os/shutil/Path mutators, subprocess/os.system/exec family argv, hermes_tools terminal/write_file/patch/execute_code, literal exec/eval) and evaluates their path/mode operands over a bounded flow-insensitive scalar domain (string +, f-strings, %/format holes, Path `/`, os.path.join, joinpath, per-scope bindings, call-site parameter binding). Strings outside a recognized operand are data. Not contained: indirect callable aliases (`f = os.remove`), getattr/reflection, attribute/class stores, lambda parameters, `*args`/`**kwargs` and method parameters, user-function return values, tuple unpacking in loop targets, match-statement captures, str join/replace/slice results, non-literal module names, loops over runtime listings, unknown helper libraries. Flow-insensitivity may hold a read-then-unrelated-write that reuses one variable name; unused functions with recognized writes may hold. Shadowed builtins are still treated as builtins. Unparsable code or code beyond source/node/nesting/work bounds keeps the baseline keyword co-occurrence rule (protected name, also after literal `+` folding, plus a Python write, shell write or copy/move/chmod/chown/mkdir/symlink/link/touch/dump keyword); a bound never yields "no mutation". One top-level `_tamper` call shares one Python character-work budget (16Mi) and one shell-analyzer budget (1Mi units) across every nested Python/shell analysis (python -c children, exec code, subprocess/os.system shell strings); identical nested shell texts at the same Python nesting depth are analyzed once per call. Nested shell text over 262144 characters is a bound. Exhaustion of the shared shell budget holds the whole code (see the shell legacy floor paragraph). Exhaustion of the Python budget applies the baseline rule to the code being analyzed at that point (the outer Python code for outer sites; the nested code for exec/python -c children, whose baseline hit holds; otherwise an exhausted budget escalates the enclosing code to the baseline rule as well). Issues are never holds and never authority.
- Concurrent tools already admitted before a denial, background process results and cross-host activity are not retroactively prevented.
- Full legacy migration, batch attribution, crash durability, strict complete schema validation and failure-path coverage are not yet accepted.

## Why the prototype failed
Problem: original33 tests passed while independent49 found34 gaps.
Root (happened): TTL, identity exemptions and agent-writable grant claims were treated as authority.
Root (not caught): prototype tests asserted those bypasses and omitted native envelope/trust-negative behaviors; missing-module errors were not behavioral RED.
Recurrence: correction of the same unpublished prototype, not a claim of deployed regression.
Countermeasures: explicit no-authority contract, behavioral baseline assertions, preserved independent probes and independent review gates. Full chain remains open until complete acceptance and deployment proof.
